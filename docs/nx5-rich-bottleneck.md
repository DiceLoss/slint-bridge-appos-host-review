# NX5 富列表源缓存瓶颈与优化

2026-10-14，实现 `1225593`，Slint `22804ff`。基线为[奇数坐标优化](nx5-odd-blend.md)的 `b1164e4`，同一 NX5 #233、启动 ID `4aa4f5d2-8de2-42cb-9c2b-44c3e74d6e2b`。本轮不改变 100 项实例、PNG/SVG/文本内容、布局、SDK、驱动或双页完成契约。

## 为什么混合增加，帧率却几乎不变

TDE 操作次数不能代表整帧工作量。旧版逐次 LRU 只有两个源槽，一帧却交替使用全屏背景和两种卡片底图；小图会把全屏背景淘汰，下一帧又重新准备 1024×600 源像素。奇数位置优化增加了硬件混合，但没有消除这种重复 CPU 工作。

分段计时覆盖窗口准备/布局、脏区计算、实际绘制、源准备、TDE 作业及分段写页。原生耗时属于绘制时间的子集，不能把下表所有行相加。纵向旧/新策略使用同一个诊断二进制切换；横向基线用初版分段探针，新版探针额外细分源转换和刷新，生产逻辑相同。正式性能另用移除探针后的 release 测量。

| --- | ---: | ---: |
| 渲染总耗时 | 71.89 → 49.76 | 80.62 → 58.42 |
| 窗口准备/布局 | 1.83 → 1.79 | 2.22 → 2.22 |
| 脏区计算 | 8.12 → 8.14 | 10.24 → 10.14 |
| 实际绘制，含 TDE 路径 | 61.89 → 39.78 | 68.12 → 46.01 |
| TDE 源准备 | 28.70 → 6.44 | 29.45 → 7.24 |
| TDE 完成等待 | 5.76 → 5.80 | 5.57 → 5.60 |
| 物理页写入 | 3.39 → 3.42 | 3.74 → 3.72 |
| 写页前等待已有提交 | 0.007 → 0.007 | 0.008 → 0.007 |

纵向旧策略中，全幅源转换约 **24.07 ms/帧**，全幅源缓存刷新仅约 **0.54 ms/帧**。新策略的测量窗口中全幅源转换、刷新及上传次数均为零，背景已在预热时缓存；小图转换约 5.99 ms/帧、刷新约 0.41 ms/帧。主因是重复准备大图，不能归因为硬件等待或刷新 ioctl。

纵向源上传按像素量估算：旧策略每帧约 0.98 次全幅和 1.90 次卡片源，新策略为 0 次全幅和 2.96 次卡片源。按 614400 / 89600 像素计算，上传准备量从约 77.3 万降为 26.6 万像素/帧，减少约 **66%**。小图上传次数增加，但避免的大图工作更多；单看缓存命中次数百分比也会掩盖这类收益。

当前绘制与提交重叠，旧提交在新帧写页前已基本完成。约 29 FPS 的板级提交上限不是这次 11–12 FPS 的主要限制。优化后仍有约 8–10 ms 脏区计算和其他软件绘制，以及 TDE 目标 alpha 检查/修正等开销；本轮没有以减少列表内容或扩大裁剪换取性能。

## 改动与复现

保留两个源槽，先选空槽，再淘汰最后使用帧较早的源；同帧使用的源优先保留像素量较大的纹理。源准备处理整张图，因此比较原图像素量，不比较裁剪后的可见面积。大图一旦退出活跃集合，其帧号变旧，可以被新内容淘汰，不永久固定背景槽。缓存键的图像身份、整体透明度和混合 X/Y 奇偶相位规则不变。

回归通过真实 Slint 绘制“背景＋四个交替前景”的调用序列：旧策略连续 8 帧上传背景 8 次，新策略仅 1 次；每次缓存命中还核对源字节，隐藏背景后验证两个活跃前景都可复用。此用例先失败再修复，避免仅测试独立的替换算法。没有增加源槽、像素缓冲或 MMZ 分配。

临时 `ITIMER_PROF` 地址采样未收到样本，不能用于热点结论，原始零样本保留。随后使用上述低频累计分段计时。临时探针、策略切换环境变量和采样库均未进入正式版；外部 Slint 的诊断改动已恢复，原有用户文件保留。

主机 feature 矩阵、格式、严格 Clippy、缓存与像素回归、原生 ASan/UBSan 故障/边界测试及 ARM 构建通过。新增 Slint 测试组件最初触发隐式 export 弃用警告，改为显式 export 后严格 Clippy 通过；首次原生检查缺少 SDK include 环境变量，按设备配置补齐后通过。原始失败日志保留。

原始证据位于本地忽略目录 `evidence/nx5-rich-bottleneck/2026-10-14/`，需另行取得。`phase-*` 保存初次计时，`cache-old-vertical/` 与 `cache-new-*` 保存策略对照；`phase-summary.json` 给出计数边界差分，不能把诊断版本的 CPU 或帧率当作最终正式版成绩。

## 正式版验收方法

正式 `1225593` 不含计时探针或地址采样。CPU/RSS 和 FPS 使用不同的新进程：前者关闭 trace、截图与事件录制，以设备 uptime 和 `/proc/PID/stat` 差分计算单核 CPU，约每秒采样 RSS；后者只使用既有每 150 次成功 PAN 的低频日志。每方向先预热至少 8 秒，资源窗口至少 45 秒、帧率窗口至少 90 秒，丢弃跨阶段开始的首批。每个手势核对实际位移并保持在列表内部，避免端点停留。原生 MCP 查询、手势插值及等待均包含在负载中。

无探针基线取上一轮同启动的 `b1164e4`；本轮同诊断二进制的新旧策略切换进一步验证成本差异，但不拿其帧率替代正式版成绩。该顺序对照不是多轮随机化实验，不提供误差置信区间。

独占硬件测试 `nx5_hardware_compare` 与 `nx5_demo_pages_match_full_frames` 通过：奇数位置、alpha/整体透明度、裁剪、写时复制缓存、80 帧增量重绘和全幅源 padding 最大通道差不超过 1；不透明复制精确一致。另有 100 帧 TDE / 内存双页对照通过，两项正常退出均释放 VO，MMZ 回到 4900 KiB / 2 块。

正式应用横纵两方向均完整观察到全部 100 个稳定 ID，宽幅拖动、锁定轴、拖动不误选、首末端夹紧和选择通过；六张受内存保护的原生截图完成。采集前最低可用内存约 17 MiB，均高于 16 MiB 保护线。完整交互进程正常退出。截图是重新软件绘制的参考，物理页另行核验。

## 正式版性能结果

| 方向 | 完成提交 FPS：基线 → 新版 | 提升 | CPU：基线 → 新版（单核） | 新 RSS 均值 / 范围（MiB） |
| --- | --- | --- | --- | --- |
| 纵向 | 12.58 → **17.52** | **39.3%** | 92.74% → 89.53% | 18.03 / 18.02–18.06 |
| 横向 | 11.55 → **15.51** | **34.3%** | 93.83% → 91.72% | 18.28 / 18.15–18.34 |

每个方向各统计 1500 次有效完成提交，合计 3000 次。纵向 FPS 窗口 90.63 秒、33 次手势，批次范围 17.33–17.61；横向 99.32 秒、10 次手势，范围 15.43–15.70。资源窗口分别为 46.04 秒 / 17 次手势和 49.49 秒 / 5 次手势，均为 3 线程、无新增 major page fault。相对基线，RSS 均值分别增加约 74 / 35 KiB；MMZ 保持 **12140 KiB / 5 块**。

TDE 完整绘制计数窗口两个方向各 1500 帧，混合分别为 3.04 / 3.28 次/帧，复制 0.98 / 0.99 次/帧，错误均为 0。混合量与奇数优化基线接近，帧率改善来自减少源准备，而非进一步增加混合调用。按调用次数计算的源缓存命中率为 26.23% / 23.72%，低于基线 27.99% / 30.55%；命中的大背景节省了更多像素工作，所以次数比例不能代替缓存收益或 TDE 硬件忙碌率。

诊断阶段设置的两个方向至少 15 FPS 检查线由基线失败转为正式版通过。帧率仍低于板级约 29 FPS 的提交上限；剩余脏区计算、软件绘制和同步 TDE 工作保留，未宣称消除所有瓶颈。完整窗口与计数见 `*-resources/`、`*-fps/`、`results.json` 和 `tde-counters.json`。

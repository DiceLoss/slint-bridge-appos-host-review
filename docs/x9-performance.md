# X9 纯 framebuffer 富列表性能

2026-10-14（北京时间），在已接入的 X9 / Lombo N7、Linux `3.10.100 #452` 上测量正式 `showcase-06`。库代码 `8604707`，Slint `ea7d0ae`，ELF SHA256 为 `568791f1c3e64c23154ae537af46f882023c346a58be6e15205d24732f1cb289`。物理面板 800×1280、顺时针 90°、逻辑界面 1280×800，CPU 软件绘制、fbdev 双页写入，DRM 匹配事件确认提交完成。

## 结果

CPU 以**占满一个核心为 100%**；本机双核，合计上限为 200%。RSS 来自不含帧率探针的新进程，FPS 来自另一个使用同一 ELF 的新进程。

| 场景 | 完成提交 FPS | 平均 CPU | 平均 RSS / 范围（MiB） | 本次进程 VmHWM（MiB） |
| --- | ---: | ---: | ---: | ---: |
| 初始 Controls 静态页 | 0（无新提交） | 0.45% | 13.60 / 13.60–13.60 | 14.49 |
| 富列表纵向连续滑动 | **6.64** | **98.14%** | **17.53 / 17.52–17.54** | 17.54 |
| 富列表横向连续滑动 | **10.73** | **98.31%** | **17.75 / 17.71–17.78** | 17.78 |
| 返回 Controls 静态页 | 0（无新提交） | 0.36% | 17.84 / 17.84–17.84 | 17.84 |

静态 0 FPS 表示按需绘制没有产生新提交，不表示显示停止。纵向、横向停止滑动后，富列表页 CPU 分别降到 0.50% / 0.33%，完成提交同样为 0。

| 连续滑动 | FPS 有效窗口 | 完成帧数 | 帧间隔中位数 / P95 / 最大值 | 资源有效窗口 | 完整手势数 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 纵向 | 63.11 s | 419 | 141.86 / 157.61 / 204.82 ms | 63.11 s | 9 |
| 横向 | 68.12 s | 731 | 94.55 / 94.58 / 157.67 ms | 68.12 s | 5 |

纵向比横向更慢，两者均接近满单核 CPU；这是低帧率滚动，不能称为流畅的 30/60 FPS。当前数据表明 CPU 工作量是值得进一步定位的方向，但本轮没有把 PNG/SVG、文字、混合、旋转写页与 MCP 调度分别计时，不能据此给某个函数分配开销比例。

## 滑动与采样条件

- 使用原有 100 项 Rich list、PNG 背景、SVG 图标和多行文字，保留现有裁剪及缓存；没有改变内容或 UI 布局。
- 每个方向先定位到列表内部，连续拖动预热至少 10 秒，然后运行至少 60 秒，完成最后一个手势再结束。本轮纵向动作窗口 66.31–66.36 秒、横向 71.40–71.41 秒，两轮耗时接近。
- 每次手势检查真实内容位移超过视口 40%、锁定轴无漂移、没有到达端点及误选。纵向视口 540 px，单次位移至少 479 px；横向视口 800 px，单次至少 767 px。采样位于中段，本轮未触及预设的边界换向阈值。
- 使用 Slint 原生 MCP 的查询和拖动；查询、插值与等待包含在负载中。它不是固定频率的实体手指/evdev 输入，不用于触摸延迟结论。
- 采样期间不截图、不录制输入。CPU governor 保持 `interactive`；静态窗口为 312 MHz，滑动基本为 912 MHz，无探针横向窗口有一个 720 MHz 样本，未强制改频。

## 计数与内存口径

资源进程 PID 2238，帧率进程 PID 2282，均为本次新启动；这些 PID 只作为历史记录。外部观察器每秒读取 `/proc/PID/stat`、`status` 和设备单调时钟，按 `CLK_TCK=100` 差分 CPU，校验进程 starttime。分析统一排除首个样本并将末端限制在动作窗口内部，避免阶段切换、导航和加载混入稳态数据。两个观察器正常退出，应用日志没有提交或渲染错误。

FPS 探针仅转发原 ioctl/read：记录成功请求的 fd/cookie，在返回的 32 字节 `DRM_EVENT_FLIP_COMPLETE` 匹配后记单调时间。启动同步、预热及阶段外事件不计入上述有效窗口。全程共 1,533 个匹配完成事件，错误标志为 0，无溢出、错配或重复时间戳；没有使用 UI timer、PAN 返回次数或普通 VSYNC 作为 FPS。

探针的固定映射为 262,160 字节，按需触页；主表 CPU/RSS 不含该映射。带探针窗口 CPU 为纵向 98.16%、横向 98.30%，与无探针差不足 0.02 个百分点；平均 RSS 分别多约 21 / 33 KiB。该顺序对照支持探针干扰较小，不是“开销为零”的证明。外部观察器本身在滑动时约占单核 0.16%–0.18%，未计入应用 CPU。

本轮全部窗口保持 3 个应用线程，没有新增 major page fault。纵向 RSS 范围差 28 KiB，横向差 76 KiB；返回静态页后 RSS 保持约 17.84 MiB，没有回到首次进入富列表前的 13.60 MiB。这是本轮短时测量，不能代替长时间内存增长测试。

RSS 不是设备总占用：实测 `/proc/PID/smaps` 中 `/dev/fb0` 的 I/O 映射大小为 8000 KiB（**7.81 MiB**），Rss/Pss 均为 0，故既有双 framebuffer 不在上表 RSS 内。tmpfs 中的部署文件也占 RAM，且与已映射文件页可能重叠，不能直接与 RSS 相加。该固件没有 MemAvailable，本轮记录 MemFree；无探针滑动窗口最低约 95.76 MiB。

## 复现与收尾

工具和命令见 [X9 性能工具](../test-app/tools/x9/README.md#富列表性能采样)。新增 C 工具通过主机及 X9 `-Wall -Wextra -Werror` 编译；完成事件计数负例测试及两项 Python 分析器回归通过。未修改库/Slint/应用源码或构建配置，本轮无需重新运行与诊断工具无关的渲染回归。

原始 CSV、完成事件、阶段手势、应用日志、结果及摘要位于本地忽略目录 `evidence/x9-performance/2026-10-14/`；检出仓库需另行获取，重放历史数据不等于重新采样。`resources-summary.json` / `fps-summary.json` 分别保存两轮统计，`results.json` 为主表合并结果。

结束后恢复不含探针的正式常驻进程，观测 PID **2367**，停在富列表纵向起点、100 项、无选中项；程序摘要不变，KD_GRAPHICS 保持启用，maps 中无计数/故障注入库。新进程在静态富列表时 RSS / VmHWM 为 17840 KiB；不与上表两个测量进程的峰值混用。临时采样文件核对 SHA256 后归档清理，当前环境见 [设备快照](../test-app/devices/x9/current-target.json)。

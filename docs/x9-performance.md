# X9 性能与流水线分析

本篇合并 X9 早期富列表基线、旋转/写页优化以及流水线调查。设备为 Lombo N7 / Linux #452，物理 800×1280、顺时针 90°、逻辑 1280×800，同一字体和 100 项内容。CPU 为单核 100% 口径；FPS 计成功提交对应的 DRM 匹配完成事件。

显示契约与初始化问题见 [X9 接入报告](x9-framebuffer.md)，现行构建/运行见 [设备说明](../test-app/devices/x9/README.md)。后续批量纹理混合单独汇总在 [Slint 优化对照](slint-optimization.md#x9-texture-neon)，不与本篇阶段收益混算。

## 旋转分块与不透明写页

2026-10-14 至 15 日，`8604707` + Slint `ea7d0ae` → `cacf98f` + Slint `fa6a6d0`（showcase 07）。保持界面、分辨率和双页契约。32×32 分块改善旋转纹理源列访问；8×64 更慢，64×16 纵向略快但横向更慢，故采用两方向较均衡的 32×32。没有硬件 cache-miss 计数，局部性解释来自代码和受控比较。

不透明写页按整段检查 alpha，再批量换通道；动态页写入像素数不变。阶段中位数如下，后台等待与下一帧绘制重叠，不能简单相加预测 FPS。

| 阶段 | 纵向基线 → 优化 | 横向基线 → 优化 |
| --- | ---: | ---: |
| 绘制（含旋转） | 128.52 → **91.09 ms** | 79.92 → **59.66 ms** |
| framebuffer 写页 | 19.06 → **5.09 ms** | 11.83 → **3.17 ms** |
| 写入像素数 | 432,000 → 432,000 | 约 262,000 → 约 262,000 |
| 写页分段数 | 17 → 5 | 12 → 4 |
| PAN ioctl | 0.076 → 0.076 ms | 0.076 → 0.076 ms |
| 提交到匹配事件完成 | 8.48 → 8.06 ms | 8.22 → 8.78 ms |

正式无阶段探针结果：

| 场景 | 基线 FPS → 优化 FPS | 提升 | CPU 基线 → 优化（单核 100%） | RSS 基线 → 优化 |
| --- | ---: | ---: | ---: | ---: |
| 纵向连续滑动 | 6.64 → **10.21** | **53.7%** | 98.14% → 98.16% | 17.53 → 17.50 MiB |
| 横向连续滑动 | 10.73 → **15.55** | **44.9%** | 98.31% → 98.17% | 17.75 → 17.73 MiB |

纵向 P95 降为 110.33 ms；横向最大间隔增至 220.63 ms，因此不能声称消除了长尾。CPU 仍接近单核满载，收益为同样占用下更多完成帧。两张实际前台页与同字体、同旋转参考共 2,048,000 像素一致；不是逐扫描帧的无撕裂证明。证据：`evidence/x9-optimization/2026-10-14/`。

## 流水线边界与后续方向

2026-10-15 对同一 showcase 07 做只读源码、ELF 和设备核对；性能值仍来自上一轮，未运行新负载。当前时序详见 [平台说明](software-platform.md#事件循环) 和 [时序图](diagrams/runtime-sequence.html)：

- UI 线程执行输入/业务、Slint render、读取唯一保留画布并分段写物理后台页；render 与写页串行。
- `fb-present` 执行 PAN、DRM 匹配完成及模式复核，可与下一帧绘制重叠；成功确认后才改变页角色。
- 该版本写页已经有编译器生成的 NEON，已定位纹理循环仍是标量；后者已在后续 Slint 批量优化中处理，不能继续把它列为未实施项。

当时 render 约 91 / 60 ms，写页约 5 / 3 ms，完成等待约 8 ms 且已在后台。把写页移到第二核必须先获得不可变源；增加整帧复制可能抵消收益。直接 render 到物理后台页还可能破坏已隐藏的完成等待，因此不能只凭“少一次 copy”判断更快。

在该调查阶段，尚未验证的候选包括重复缩放/底图缓存、单帧独立区域并行；后续不透明背景缓存实测见[本篇对照](#x9-background-cache)。Slint renderer 的 Rc/RefCell 及同步 UI 访问不能直接跨线程共享；任何并行化须保留透明层叠、裁剪、缓存及脏区顺序。原调查没有按核/线程量化全部负载，也没有精确逐帧重叠测量或硬件 cache-miss 计数。证据：`evidence/x9-pipeline-neon/2026-10-15/`，为只读与反汇编记录，不是新性能成绩。

## 不透明背景缓存对照

2026-10-16，在同一 X9 #452 上比较主分支 `57ebb54` 与本轮背景缓存实现；两版均使用锁定的 Slint `c878901`，相同 X9 release 构建命令、`fbdev,slint/mcp`、DejaVuSans.ttf、800×1280 物理画布和 90° 旋转。没有修改界面、素材、计时器、列表数量或 Slint 源码。缓存准入、精度与容量边界集中在 [平台说明](software-platform.md#framebuffer-软件路径)。

基线 ELF 为 13,735,188 字节，SHA256 `e7fd2ce76784c33245e2eb9bb7992739c5da03da499a07bb4597e9eefae0147e`；候选为 13,737,644 字节，SHA256 `e689888b952bbafa33270c84197c56326ffbfc7c53888d6f4dd504b57bd4e8d2`。候选只增加 fbdev 的单项背景缓存，既有物理双页、保留画布和提交线程保持不变。

使用 `profile-rich-list.py --seconds 60`，每方向在列表内部预热至少 10 秒，确认位移超过视口 40%、轴向不漂移、没有误选或停在边界。资源使用无探针新进程；FPS 使用独立新进程和 `count-flips.so`，按同窗口内成功匹配的 DRM 完成事件计数。性能窗口不截图、不录制输入。两版资源进程在测量前均经过同样四个静态画面采集，RSS 是该预热条件下的结果。

| 场景 | 基线 → 缓存完成 FPS | 提升 | 帧间隔 P95（ms） | CPU（单核 100%） | 平均 RSS（MiB） |
| --- | ---: | ---: | ---: | ---: | ---: |
| 纵向滑动 | 12.80 → **19.40** | **51.6%** | 78.82 → **63.06** | 98.12% → 98.21% | 18.34 → 22.27 |
| 横向滑动 | 19.94 → **30.06** | **50.7%** | 63.06 → **47.30** | 98.09% → 98.45% | 18.40 → 22.39 |

基线 FPS 有效纵/横窗口为 64.120 / 58.110 秒，821 / 1159 次完成；候选为 61.118 / 58.117 秒，1186 / 1747 次完成。基线资源窗口为 56.10 / 58.11 秒，候选为 61.12 / 58.11 秒。每版本每方向只有一个正式长窗口，未做多轮统计显著性分析；沿用设备原有调频，活动窗口采到 312/504/912 MHz 的阶段性变化，并未锁定频率。

收益是在近似相同的单核饱和占用下提交更多帧，不能称为 CPU 降低 50%。额外 RSS 约 3.9～4.0 MiB，与一张 800×1280 RGBA 派生背景相符；线程数保持 3，返回 Controls 后 CPU 分别为 0.45% / 0.36%。未单独测量冷启动及首帧缓存生成耗时。基于这轮收益和内存代价，保留缓存实现。

### 画面与回归

- 主机及 X9 ARM release 的同一差分回归通过：RGB、RGBA、预乘 RGBA，四个旋转方向，共 144 帧、1,465,800 像素；覆盖局部重绘、嵌套裁剪、源写时复制/替换、透明度、隐藏及尺寸变化。参考为 Slint 原路径的完整重绘；候选使用保留缓冲和缓存，并断言实际发生复用。
- Controls 48%、Image scaling 125%、富列表纵向固定偏移和横向固定偏移，四张实际前台页共 **4,096,000 像素逐字节一致**，覆盖 yoffset=0 和 1280。四张同状态原生 MCP 截图也完全一致。物理页 SHA256 和图片保存在本轮证据中。
- feature 矩阵、格式检查、NX5 TDE/MCP 与 fbdev/MCP 的严格 Clippy 通过；X9 showcase 和 ARM 差分测试交叉构建通过。翻页计数器与性能分析工具的主机回归通过。
- 四个测量应用均以 `--seconds` 正常退出；原 `showcase-08` 的信号停止另行记录，停止后通过匹配完成事件恢复控制台，不把它算作正常析构验证。最终运行无探针的优化版，当前路径、摘要及恢复材料见 [设备快照](../test-app/devices/x9/current-target.json)。

候选资源观察器第一次读到上一阶段遗留的 `done`，只产生表头，未计入结果；在预热及全部有效窗口之前重启观察器，使用绑定同一应用 starttime 的 `resources-restarted.csv`。原空 CSV 保留，后续启动脚本先重置阶段标记。没有把缺失采样当作通过结果。

本地原始证据为 `evidence/x9-background-cache/2026-10-16/`，入口 `verification.json`；该目录被忽略，其他机器需另行取得。物理页是静态采样，MCP 手势不是实体手指；本轮没有新增连续扫描输出、无撕裂或触摸到扫描端到端时延认证，也没有部署 NX5。

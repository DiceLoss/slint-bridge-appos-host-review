# NX5 CPU/TDE 共享 MMZ 画布实测

2026-10-13，USB1 / ADB `192.168.1.151:5555`、Linux 4.9.138 #233、同一启动 ID `938c34d4-456a-4b1a-b532-678c0f92efd0`。基线为 `fdb0f0e`，Slint 为 `22804ff`，使用 `.cargo/nx5.toml` Cortex-A7/NEON 预设及原 SDK。原始档案位于本地 `evidence/nx5-shared-canvas/2026-10-13/`，不随 Git 分发，需另行取得。

## 变更与所有权

`FY_MPI_SYS_MmzAlloc_Cached` 返回物理地址和已映射的 CPU 虚拟地址。当前保留画布直接使用这个映射：Slint 软件绘制访问虚拟地址，TDE 描述符使用物理地址。无需额外 mmap，不再保留独立堆画布，不再将 TDE 结果拷回堆，也不再为混合预先把堆目标拷入 MMZ。

作业前同步 CPU 缓存，阻塞 `EndJob` 确认结束后再次同步缓存，随后才允许 CPU 读取或绘制。两个源图缓存槽仍保留。1024×600 的 TDE MMZ 仍为 7200 KiB / 3 块；加上原 framebuffer/VPPU，活动总量为 12100 KiB / 5 块。省去约 2400 KiB 的堆画布，增加 4 KiB 的错误隔离行；RSS 包含映射、文件页等，不能直接等同于总物理内存节省。

硬件已完成但返回失败时，共享画布可能含部分结果。后续 Slint 回调先写入隔离行，随后禁用 TDE，在原 MMZ 映射上强制全量软件重绘，并恢复原 `ReusedBuffer` 模式。画布继续持有 MMZ 与 SDK 引用，不因加速器禁用而被释放。若 DMA 完成状态未知，则不允许后续 CPU 读写画布，返回错误并保持原有资源隔离。

仍是两张物理 framebuffer、至多一笔在途提交及一帧预渲染。MMZ 画布不是第三张扫描页。写显示页仍由 CPU/NEON 完成 RGBA 反预乘、红蓝交换及 NX5 alpha 编码；本轮没有实现 TDE 直接复制到扫描页。

## 渲染与填充

512×384、真实 SDK、真实 Slint renderer；纹理缓存预热后测 60 帧，填充测 100 帧。计时包含软件绘制、硬件提交及缓存同步，不含 framebuffer 写页和 PAN。旧值来自上一轮同板 [填充/混合档案](nx5-fill-blend.md)，为先后运行对照，不能作为隔离每一项成本的精确归因。

| 场景 | 旧独立 MMZ / 回拷 | 共享 MMZ | 当前软件参考 |
| --- | ---: | ---: | ---: |
| 不透明图像复制 | 4.619 ms | 2.330 ms | 13.567 ms |
| 图像整体 opacity=50%，不透明源 | 约 11.14 ms | 9.756 ms | 33.102 ms |
| 图像整体 opacity=50%，straight RGBA | 约 11.14 ms | 9.758 ms | 32.953 ms |
| 全幅纯色 QuickFill | 3.478 ms | 1.203 ms | 0.592 ms |

另测 16×16 至 1024×600、宽条/方块/分段、透明/不透明共 22 组，轮换 TDE、CPU 堆和 CPU MMZ 三条路径，70 轮丢弃前 10 轮。计时后用哨兵重置画布，单独执行 TDE 再检查，避免 CPU 同址填充覆盖硬件错误；所有像素及边界通过。最终复验全屏不透明 TDE 均值 **2.856 ms**，CPU 写 MMZ **1.686 ms**、写堆 **1.700 ms**；旧 TDE 含回拷为 9.344 ms。所有 22 组仍由 CPU 写 MMZ 更快，在当前面板尺寸内没有找到填充交叉点。因此保留 `SLINT_BRIDGE_TDE_FILL=1` 对照开关，默认继续 CPU 填充。

同一真实 SDK 分派检查中，被 TDE 接受的填充/复制/混合操作，其后对应的软件行访问次数均为 **0**；软件回退用例没有 TDE 成功作业。没有发现 TDE 成功后又由软件重复绘制同一操作。底图与文字等不同操作依次绘制属于正常合成。

证据：`compare-01.log`、`area-01.log`、`area-final.log`。复制精确，混合最大通道差 1；80 帧增量对照通过。共享画布持有 MMZ 的已知错误回退也通过真实映射测试；未在真实硬件上制造 DMA 挂死。

## 真实 framebuffer 写页

新增 `framebuffer::nx5_writeback::shared_mmz_writeback_matches_staged_pixels`：源为 TDE 填充后的共享 MMZ；目标为实际 framebuffer 的可用后台页，使用生产 `Layout::write_row` 和阻塞提交完成契约。对照路径先按行 MMZ→堆，再执行相同像素转换。两路径逐轮换序，每组预热 5 轮、测量 30 轮；共 210 次真实页面呈现。计时只含暂存和转换写入，不含填充、PAN 等待或页读回。

| alpha | 共享 MMZ 直接转换写页均值 | 对照暂存均值 | 对照转换写页均值 | 对照合计均值 |
| --- | ---: | ---: | ---: | ---: |
| 0 | 7.109 ms | 6.766 ms | 8.372 ms | 15.138 ms |
| 127 | 52.014 ms | 6.756 ms | 53.589 ms | 60.346 ms |
| 255 | 6.648 ms | 6.752 ms | 7.941 ms | 14.692 ms |

共享路径取得切片约 0.003 ms，未计入表内转换列。每个 alpha/路径的最后一张实际显示页均读回全幅检查，共 **3686400 像素完全一致**；不是对全部 210 帧逐帧采样。测试正常退出后 VO 关闭、MMZ 恢复 4900 KiB / 2 块、独占锁释放。

首次共享版本全透明写页仍约 51.137 ms，定位为零 alpha 块落入逐像素转换。加入 16 像素全透明 NEON 清零后降至上表的 7.109 ms；不透明快速路径不变。半透明仍保留精确反预乘，未优化其约 52 ms 的全屏成本。对应证据为 `writeback-before-zero-fast.log`、`writeback-final.log`。

## 验证边界

- 主机 feature 矩阵、格式、严格 Clippy 和 ARM release 构建通过；C 故障注入 ASan/UBSan 通过。Rust 用部分写入故障先复现错误，再验证整帧重绘和 `ReusedBuffer` 模式恢复，以及未知 DMA 后画布不再被软件修改。
- ARM CPU NEON 检查全部 channel/alpha 组合、两种输出 alpha 量程、0–65 像素长度、0–3 字节偏移和前后保护区；结果完全一致，源不变。该项不加载 SDK。
- 100 帧真实 TDE + 内存文件承载双页的演示比较通过，最大通道差 1；该项不等同于真实扫描输出检查。真实页另由上述写页测试验证。
- 旧常驻进程在静态页、提交线程空闲后由 SIGTERM 停止，内核强制回收它的 MMZ；该记录不计为新测试正常退出成功。所有独占 SDK 测试结束后先核对 VO、MMZ 和锁，再恢复常驻界面。
- 本轮没有重做 WBC 合成、实体触摸时延或逐帧无撕裂采样；原报告的这些成绩保留原构建范围。MCP 截图也不能证明硬件画布正确。

## 展示程序复测

最终展示二进制 SHA256 为 `255226ed8d7362878b20a1d926d8dde07a06ea6864731f43805a0f2e3908bb40`，与实机副本核对一致。有限运行 180 秒（PID 3893）正常退出；VO 关闭、MMZ 4900 KiB / 2 块、显示锁可重新取得。

六页 Slint 原生 MCP 交互及十张受内存检查保护的截图通过，227 条录制事件、零丢失/未知。列表预热 8 秒、滚动约 35.7 秒，丢弃跨阶段统计批次后保留 6 批、900 次成功提交，均为 **29.00 FPS**。该滚动窗口 CPU 均值约 **76.8% 单核**；结束 RSS **15660 KiB**，该进程 VmHWM **20892 KiB**（包含此前截图）。该短窗口不等同于全部动态场景长期性能；没有新增实体 evdev 时延数据。

最后一条 trace 为 4050 帧、3927 次 TDE copy、3926 次缓存命中、0 错误。默认纯色填充未发起 TDE，图像混合由独立硬件用例覆盖。证据见 `device-ui/summary.json`、`list-window/result.json` 与 `showcase/remote/`。

# Slint 纹理批量混合与两设备对照

2026-10-15 的三轮实验分别验证 X9 加速、NX5 兼容性及 NX5 Pixel 接入。所有数字保留各轮自身基线，不把不同轮次拼成一次前后对照。当前依赖配置和升级约定见 [平台说明](software-platform.md#构建依赖)。

## 算法与适配边界

Slint `5cfde5f` 增加带默认实现的 `TargetPixel::blend_sampled_slice`。优化入口限定预乘 RGBA、无着色、整体 alpha=255 的纹理路径。原采样器负责坐标、裁剪、旋转和缩放；每像素按顺序采样一次。预乘 RGBA 目标每批最多 32 像素，使用 128 字节栈缓冲；全不透明批次直接复制，其余精确整数混合，便于生成 SIMD。字节乘积范围内 `(v + 1 + (v >> 8)) >> 8` 精确等于 `floor(v / 255)`。

X9 使用该目标像素类型。NX5 TDE 的 `Pixel` 原先使用默认逐像素实现，后续才通过透明包装切片委托到批量实现。旧适配层不必实现新方法；新 NX5 委托需要包含此接口的 Slint。SDK/TDE 提交、未知 DMA 隔离、双页和一笔在途契约均未改变。

三轮的性能窗口不截图或录制输入，资源和完成 FPS 分进程采集。每版本每方向仅一个正式长窗口，未做多轮统计显著性分析。两设备的原始图像、日志、源码与 ELF 摘要保存在下述本地证据目录，不随 Git 分发。

## 采用与维护

X9 的约 25%–28% 完成 FPS 收益支持保留公共优化；NX5 单独收益不足以支撑专属分支。项目已选择两设备统一使用同源 Slint，保留 NX5 委托。升级时检查新版是否已有等价实现，再迁移仍需要的补丁；像素正确、ARM 构建、向量化及正式性能分别验证。旧设备快照只说明采集时状态，运行路径与恢复策略以设备说明和实时核对为准。

## 2026-10-19：剩余 Slint 修改的回退审计

在保留 SVG 加载与栅格缓存的前提下，核查导入基线 `bcb6381` 到本地 `ad432b2` 的全部净差异：10 个文件，458 行增加、20 行删除，包含测试和注释。
本轮只读核对远端 `master` 为 `796ea9f`，与 bridge 锁文件一致；本地 `ad432b2` 的文件树与它相同，后续 SVG 下沉及其回退没有净差异。
已经撤销的 Slint 旋转分块、批量混合不再属于剩余实现。

结论：没有发现可整笔撤销且已证明保持当前功能和性能的剩余提交。
找到一处可独立精简的冗余字段，另有一处可单独恢复、但会改变文字处理配置的片段。
正式 Slint、bridge 运行代码和锁文件均未修改；实验全部在 `/tmp/` 的隔离副本中进行，没有部署或操作设备。

### 可精简的两行

`internal/renderers/software/target_pixel_buffer.rs` 的 `TextureCacheKey.image_size` 与构造处的 `image_size: image.size()` 可以一起删除。
`a2cc406` 已使 `SharedImageBuffer::eq` 先比较宽高，因此派生的键比较已通过 `image` 覆盖尺寸；剩余的 `source_rect` 继续区分裁剪视图。
这不需要撤销整个缓存键接口，也不需要修改 bridge 的消费者。

隔离候选通过原有三个缓存键回归、新增的同一外部地址/不同尺寸键回归、八个应用侧回归和四个软件路径/缓存回归。
覆盖源替换、写时复制、格式/子视图、外部所有者、四向旋转、局部重绘及回退路径。
另一个布局探针测得 x86_64 主机上的键大小从 48 字节变为 40 字节；它不是 ARM/RISC-V 布局测量，也不是帧率收益。
源码比较可证明删除的尺寸条件冗余；本轮没有为这两行精简宣称新的三板性能结果。

### 反向回归与验证范围

先用当前实现运行基线，再分别只撤销表中的五个正确性修复：截图、SVG 旋转、缓存淘汰、空图相等、图像尺寸相等。

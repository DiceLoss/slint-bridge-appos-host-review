# Slint 纹理批量混合与两设备对照

2026-10-15 的三轮实验分别验证 X9 加速、NX5 兼容性及 NX5 Pixel 接入。所有数字保留各轮自身基线，不把不同轮次拼成一次前后对照。当前依赖配置和升级约定见 [平台说明](software-platform.md#构建依赖)。

## 算法与适配边界

Slint `5cfde5f` 增加带默认实现的 `TargetPixel::blend_sampled_slice`。优化入口限定预乘 RGBA、无着色、整体 alpha=255 的纹理路径。原采样器负责坐标、裁剪、旋转和缩放；每像素按顺序采样一次。预乘 RGBA 目标每批最多 32 像素，使用 128 字节栈缓冲；全不透明批次直接复制，其余精确整数混合，便于生成 SIMD。字节乘积范围内 `(v + 1 + (v >> 8)) >> 8` 精确等于 `floor(v / 255)`。

X9 使用该目标像素类型。NX5 TDE 的 `Pixel` 原先使用默认逐像素实现，后续才通过透明包装切片委托到批量实现。旧适配层不必实现新方法；新 NX5 委托需要包含此接口的 Slint。SDK/TDE 提交、未知 DMA 隔离、双页和一笔在途契约均未改变。

三轮的性能窗口不截图或录制输入，资源和完成 FPS 分进程采集。每版本每方向仅一个正式长窗口，未做多轮统计显著性分析。两设备的原始图像、日志、源码与 ELF 摘要保存在下述本地证据目录，不随 Git 分发。

## X9 的渲染与整机收益

X9 #452，800×1280 物理、90°、逻辑 1280×800，Cortex-A7 hard-float、同一字体，纯软件路径不加载厂商 SDK。基线 showcase 07 为库 `cacf98f` + Slint `fa6a6d0`；候选基于库 `6ae646b` 的回归增补，运行优化在 Slint `5cfde5f`。

热点探针显示预乘 RGBA、90°、整体 alpha=255 的采样与混合占 render 的 87.18% / 82.21%。简单八像素收集试验未生成目标向量循环，反而退化，已否决；最终正式 ELF 确认纹理循环存在 NEON。以下离屏均值不含写页或显示等待：

| --- | ---: | ---: | ---: | ---: |
| 90° 纵向 | 90.31 ms | 69.86 ms | 22.64% | 1.293× |
| 90° 横向 | 59.05 ms | 44.56 ms | 24.52% | 1.325× |
| 0° 纵向 | 62.41 ms | 46.44 ms | 25.58% | 1.344× |
| 0° 横向 | 42.33 ms | 31.61 ms | 25.33% | 1.339× |

正式完成提交及无探针资源：

| --- | ---: | ---: | ---: | ---: | ---: |

| 横向 | 15.60 | 19.93 | 27.72% | 98.19% → 98.16% | 17.74 → 17.84 MiB |

CPU 仍接近单核饱和，不能声称 CPU 降低 25%。四组离屏 4,096,000 像素逐字节相同；两个实际物理前台页合计 2,048,000 像素与独立参考一致。ARM 纹理测试、八页 MCP（20 张截图）及实际 evdev 注入通过。初轮没有成功启动 CPU 观察器的窗口作废，表中只用有效重跑；诊断探针已移除。

证据：`evidence/x9-neon/2026-10-15/`。这项优化在 X9 有明显收益，但不等于保证任意应用的同等提升。

## NX5 只更新 Slint 的兼容性

NX5 #233、1024×600、0°、nx5-tde。两份应用均来自桥接库 `1736f56` 的同一临时源码，只切换 Slint `fa6a6d0` → `5cfde5f`。此时 NX5 Pixel 尚未重写批量方法，因此生产纹理路径仍逐像素混合。

| 场景 | 优化前 → 后 FPS | 变化 | 优化前 → 后 CPU | 平均 RSS |
| --- | ---: | ---: | ---: | ---: |
| 富列表纵向 | 27.48 → 27.45 | -0.11% | 79.35% → 79.42% | 17.90 → 17.97 MiB |
| 富列表横向 | 25.88 → 25.77 | -0.41% | 86.11% → 86.26% | 18.16 → 18.23 MiB |

两项 ARM 纹理、六项硬件、八页 MCP、evdev 和背景 23 阶段双页通过。两方向物理页合计 1,228,800 像素前后逐字节相同；背景 27,648,000 像素正确。结果接近，不能从这一轮推出 X9 加速也已经作用于 NX5 Pixel。

证据：`evidence/nx5-texture-neon/2026-10-15/`。

## NX5 Pixel 接入后的对照

桥接库基线 `9a4cdcc`，前后都使用 Slint `5cfde5f`、相同构建路径/参数；仅增加 Pixel 的采样批量委托。NX5 Buffer 的正式纹理循环由无对应向量混合指令变为包含 `vmull.u8`、`vadd.i16`、`vshr.u16`、`vsub.i16` 和向量存储。

| 场景 | 优化前 → 后 FPS | 变化 | 优化前 → 后 CPU | 平均 RSS |
| --- | ---: | ---: | ---: | ---: |
| 富列表纵向 | 27.53 → 27.58 | +0.16% | 79.31% → 78.66% | 17.97 → 17.69 MiB |
| 富列表横向 | 25.81 → 26.13 | +1.25% | 86.28% → 86.08% | 18.23 → 18.02 MiB |

四组 FPS 各使用 10 个完整 150 帧批次，共 6000 次成功提交。正式资源窗口为前 45.57 / 47.51 秒、后 45.13 / 47.12 秒；3 线程、MMZ 12760 KiB / 6 块不变。首次基线资源采样纵向 70.54%、横向 85.79% 仍保留；纵向有一次 3.36 秒 ADB 读取延迟且手势较少，因此另起进程重测两轴，上表使用同节奏重测。正式前后最大读取耗时为 0.086 / 0.083 秒。

1584 组 Pixel 边界在主机和 ARM 通过；六项硬件回归均正常退出并回到 MMZ 4900 KiB / 2 块。八页 MCP、19 张截图、实际 evdev 的两次点击/一次拖动（21 条事件、六个边沿 Accepted）通过。前后两方向物理页 1,228,800 像素完全一致；背景 23 阶段、45 页共 27,648,000 像素 RGB/alpha 精确一致，损坏参考 alpha 的负对照被拒绝。

恢复原 background-holes，614400 像素与测试前截图一致；测试窗口 153 条新内核记录无错误、OOM、超时或强制回收，原常驻信号退出单列。未新增 WBC、真实视频底层、实体传感器或动态扫描验证。

证据：`evidence/nx5-pixel-batch/2026-10-15/`。批量代码确实生效，但这轮 NX5 整机收益很小，不能认定为稳定加速；两个 showcase 均为 10805632 字节。

## 采用与维护

X9 的约 25%–28% 完成 FPS 收益支持保留公共优化；NX5 单独收益不足以支撑专属分支。项目已选择两设备统一使用同源 Slint，保留 NX5 委托。升级时检查新版是否已有等价实现，再迁移仍需要的补丁；像素正确、ARM 构建、向量化及正式性能分别验证。旧设备快照只说明采集时状态，运行路径与恢复策略以设备说明和实时核对为准。

## 2026-10-19：迁到适配层后的 NX5 对照

本轮比较桥接库 `f578c8e` 与 `752b741`，两者都锁定 Slint `a2cc406`。前者已经包含 Slint 内的批量混合和旋转分块；因此这里测的是迁到适配层后的**增量变化**，不是相对未优化 Slint 的总收益，也没有拆分两项算法各自的贡献。当前实现及回退条件见 [平台说明](software-platform.md)。

NX5 #233、双 Cortex-A7、1024×600 物理屏幕，启动 ID 为 `4aa4f5d2-8de2-42cb-9c2b-44c3e74d6e2b`。前后均以 `.cargo/nx5.toml`、release、`arm-unknown-linux-gnueabi`、`nx5-mma-background,slint/mcp` 构建，运行时使用默认 heap 背景、相同 SDK、字体及设备路径。Cargo.lock、应用源码和场景素材逐文件一致；只比较桥接实现变化。

每个版本运行两次 0° showcase 和两次 90° `display --textures`。富列表每轴预热约 8 秒、采样约 40 秒；旋转纹理预热约 8 秒、采样约 50 秒。富列表沿用原生 MCP 连续往返拖动，避开端点停留；其查询和手势开销计入负载。纹理场景由应用自己的定时器运动。测量期间不截图或录制输入，前后均启用相同 trace，CPU/RSS 约每秒读取一次。

FPS 来自每 150 次成功提交的日志，丢弃跨阶段开始边界的首批，按有效帧数和批次耗时汇总。CPU 的 100% 表示一个核；本板 auxv 的 `AT_CLKTCK=100` 已核对。RSS 是进程驻留内存，不包含独立记账的全部 MMZ。

共统计 10950 次成功提交。两轮重复不等于统计显著性检验；版本顺序未随机化。旋转纹理仍约占满一个核，普通富列表接近本板约 29 FPS 的提交上限。横向富列表的两轮结果均低于基线，属于本轮观测到的性能回退；这次适配层迁移没有带来新增整机 FPS 收益。2026-10-15 的历史收益不计入本轮。

另一次尝试将 showcase 旋转 90°，因最小窗口布局不适合 600×1024 逻辑尺寸而退出 1；该窗口没有进入性能统计，退出后资源也已释放。未修改应用布局以取得通过结果。首次上传因 `/tmp` 分区空间不足失败，事务归档后改用 `/run`，重新核验摘要和内存余量。测试结束恢复原音乐播放器，测试副本及控制文件按部署流程归档清理。

本轮没有新增 WBC、动态扫描、物理页逐像素或实体触摸验收，也没有测量 X9/F1。候选 showcase / display 分别为 11858304 / 5861736 字节，基线分别为 11854208 / 5857640 字节。

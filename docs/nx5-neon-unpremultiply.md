# NX5 NEON 反预乘与 framebuffer 写页优化

2026-10-13，同一 NX5 #233、1024×600、SDK 和 Slint `22804ff`，基线工程为 `32d8ead`（运行时代码仍为 `d34f436`）。原始档案在本地 `evidence/nx5-neon-unpremultiply/2026-10-13/`，不随 Git 分发，需另行取得。

## 实现与精度

本优化用于启用 `nx5-tde`、按 `.cargo/nx5.toml` 预设编译的 ARM NEON 路径；不要求某个 TDE 作业命中，TDE 不可用后的 CPU 绘制也可使用。无 NEON 构建保留原路径。

半透明输出原先逐像素查 Q16 倒数表，再对三个通道执行乘法、舍入、饱和与字节写入。本轮保留同一张倒数表和整数规则，用 NEON 每次处理 8 个像素，三个颜色通道复用两组 4-lane 倒数；一组 alpha 相同时只查表一次。

生成的 ARM 指令包含 `vmul.i32`、`vrshrn.i32`、`vqmovn.u16` 等，未使用近似浮点倒数或手写汇编。RGB 仍精确等于 `min(255, (channel*255 + alpha/2)/alpha)`，alpha=0 输出零。0–128 输出量程采用 NEON 舍入右移，等于 `(alpha+1)/2`；0–255 保留源 alpha。短尾部和其他输出量程保留原标量代码。

不透明和全透明区域使用独立、不内联的连续块快路径，仍按 16 像素转换或清零。原因是当前 GCC 5 在把半透明计算全部内联到原函数后，会将快路径的常量向量溢出到栈，导致每块重复加载；实测出现不透明写页退步。隔离后恢复并略微改善快路径，同时减少主函数寄存器压力。没有增加画布、MMZ 分配或运行时配置。

实现位于 [native.c](../src/backends/nx5/tde/native.c)，仅改变 CPU 像素转换。共享 MMZ、TDE 作业、两张物理页、脏区、缓存所有权及提交完成契约保持原有规则。

## 算法选择

临时 CPU 微基准在同一进程中轮换旧/新函数，均使用普通堆内存及逐行转换；旧函数从基线源码提取，仅改符号名。预热 5 轮后测 40 轮，不加载 SDK、不写 framebuffer。

| 候选 | 固定 alpha=127 | alpha 混合 | 观察 |
| --- | ---: | ---: | --- |
| 4 像素按 RGBA 展开 | 28.77 ms | 28.90 ms | 约为旧版的 1.94–1.97 倍 |
| 8 像素按通道展开 | 25.96 ms | 26.24 ms | 更快，但不透明路径出现退步 |
| 最终方案：连续块快路径＋统一 alpha 查表 | 22.13 ms | 25.84 ms | 相同进程旧版为 55.73 / 56.07 ms；不透明和全透明也更快 |

以上是微基准，不能替代实际写页耗时。4 像素与 8 像素方案的原始日志分别保留在 `bench-four.log`、`bench-eight.log`；中间快路径实验保留在 `bench-opaque-run.log`。最终为 `selected/remote/bench.log`，没有将中间的退步样本改写为通过。

## 真实 framebuffer 写页

使用维护中的 [probe-writeback.c](../test-app/tools/nx5/tde/probe-writeback.c)，Cortex-A7/NEON、同样的 `-O2` 参数。源为 cached MMZ，目标为真实 framebuffer 后台页；表中统计 CPU 直接转换写入，排除图案生成、读回、PAN 等待和渲染。每种图案预热 5 轮、测 30 轮；另一条 CPU-MMZ→TDE 路径仍参与轮换，但不进入生产运行。

旧值来自前一轮 [TDE 写页调查](nx5-tde-writeback.md) 的最终同板探针，新值来自本轮最终版本。属于相同程序/参数的先后对照；微基准另提供同进程轮换佐证。

| 整屏图案 | 优化前 | 优化后 | 加速比 |
| --- | ---: | ---: | ---: |
| 不透明渐变 | 6.605 ms | 6.243 ms | 1.06× |
| 全透明 | 7.018 ms | 5.835 ms | 1.20× |
| alpha=127 | 52.751 ms | 19.336 ms | 2.73× |
| alpha 0–255 渐变 | 51.612 ms | 22.885 ms | 2.26× |

最终半透明 P50/P95 为 19.341/19.573 ms，alpha 渐变为 22.893/22.935 ms。中间未隔离快路径的版本曾将不透明写页拖慢到 7.573 ms，见 `writeback-eight.log`；最终版本已消除这次退步。

CPU 转换到 MMZ 再 TDE 拷贝的最终固定半透明耗时为 23.976 ms、alpha 渐变为 27.785 ms，仍慢于 CPU 直接写页。生产路径继续使用 CPU/NEON，不把约 4.3 ms 的单独 TDE 拷贝时间当成完整转换写页时间。

## 正确性与验证范围

- 主机 ASan/UBSan 与 ARM CPU 原生回归通过。两种输出 alpha 量程分别验证全部通道/alpha 组合；新增混合 lane 的穷举，覆盖同一向量里不同 alpha 与不同 RGB，防止错误复用倒数。长度 0–65、0–3 字节偏移、透明/不透明/半透明连续块之间的切换、前后保护区和源不变均通过。ARM CPU 用例不加载真实 SDK。
- 最终 C 探针交替呈现 280 帧；四种图案、两条路径的最后一轮先向后台页写入非零哨兵，再读回全幅，共 **4915200 像素完全一致**。颜色与 alpha 用独立整数除法参考比较；源 MMZ、写入时的前台页均未变。
- C 探针正常退出，VO 关闭、MMZ 回到 4900 KiB / 2 块、显示锁释放，内核窗口没有新 MMZ 强制回收。旧常驻程序按静态页和提交空闲检查后 SIGTERM 切换，其强制回收记录单独保留。
- 此处物理页读回不代表 WBC、下层视频合成或逐帧光学扫描认证。探针设置 `FB_ACTIVATE_VBL`，生产 Rust 后端保留原 activate 标志；计时均排除 PAN，生产路径另行回归。

最终 C 探针证据为 `selected/remote/writeback.log`、`writeback-selected.json` 及该目录的内核/退出资源日志。一次串口长命令截断停在未完成输入状态，检查确认诊断未执行；清除该输入、拆分短命令并重新核对 SHA256 后完成测试，没有将这次传输问题计为像素测试结果。

生产 Rust 路径另用 `.cargo/nx5.toml` release 构建验证：`neon_writeback_boundaries` 通过；`shared_mmz_writeback_matches_staged_pixels` 使用生产 `Layout::write_row` 与原 PAN 契约，210 次呈现、最后六页共 **3686400 像素完全一致**。共享 MMZ 直接写页均值为全透明 6.130 ms、alpha=127 **19.131 ms**、不透明 6.560 ms；与 C 探针的编译参数和输入图案不同，分开记录。另有 100 帧真实 TDE＋内存文件双页的演示对照通过，最大通道差 1，不能把它当作额外物理页读回。

主机 feature 矩阵、格式、严格 Clippy 和 ARM release 构建通过。生产回归日志在 `rust/remote/`；SDK 用例正常退出后均回到 MMZ 基线并释放显示锁。最终两组物理页读回合计 **8601600 像素**，不是对所有呈现帧逐帧采样。

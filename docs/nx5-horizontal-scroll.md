# NX5 横向多屏滑动测试

2026-10-14，基于当前运行时 `a0e880c` 补齐横向大范围滑动，代码提交 `3892780`。按用户要求只测试当前版的功能、CPU、内存和帧率，没有构建旧运行时对照。库的输入、渲染、像素转换、双页提交及外部 Slint/SDK/驱动均未修改。

## 场景与自动覆盖

Devices 页新增 `Horizontal cards` / `Vertical list` 切换。横向使用原生 Flickable，复用原 18 条设备、筛选和按稳定 ID 打开详情的回调；只允许横向移动。卡片宽 232 px，间距 12 px，内容总宽 4380 px。在 NX5 1024×600 上，可视区为 770×262 px，可滚动距离 **3610 px，约 4.7 个可视宽度**。返回 Devices 页默认仍为纵向列表。

维护中的 [主机 MCP 检查](../test-app/tools/check-showcase.py) 增加左右完整遍历、两端额外拖动、纵向漂移、拖动误触、末项点击、筛选后的稳定 ID 和空状态检查。每次拖动从可见边缘卡片开始，至少跨越可视宽度的 60%；不会用短距离滑块操作替代横向列表覆盖。原生 MCP 只枚举可见元素，因此随着滚动发现卡片，并保留首项句柄测量实际内容位移。

长遍历使用每次手势独立的原生事件录制，检查 dropped/unknown 均为 0，避免超过 1024 条环形缓冲。新增横向起点、末端和返回三张截图，完整用例现在为六页、13 张截图。操作入口见[测试工程说明](../test-app/README.md#六页展示应用-showcase)。[性能工具](../test-app/tools/nx5/display/profile-showcase.py) 也新增横向阶段，每六次改变方向。

## 主机与 NX5 功能结果

- 主机完整原生 MCP 用例通过，六页和 13 张截图；feature 矩阵、格式检查、严格 Clippy、四项性能证据分析器回归及 ARM release 构建通过。
- NX5 同一 release 文件通过相同用例，观察到全部 18 张卡片。左右各 7 次手势（含端点额外拖动），跨度 588–727 px；首项 X 从 214 到 −3396 再回到 214，Y 始终为 248。端点夹紧、无误开详情、末项和筛选后的设备 18 选择、空状态均通过。
- NX5 主用例记录 226 条事件；新增横向用例 14 个短窗口共 1994 条事件，零丢失、零未知。三张新增实机 MCP 截图已人工检查排版。
- 另用只操作 Linux evdev 的回放器，执行左、右各 6 次、每次 **730 px** 的横向手势，每次 24 个移动点。12 次接触共 324 条 Slint 事件全部 Accepted，零丢失/未知，实际列表同样到达末端并返回起点，没有纵向位移或详情误触。

回放器检查 `gsl1686`、轴范围和当前无按下接触，结束时释放触摸；不加载 SDK、不操作 framebuffer。该结果是自动 evdev 输入验证，没有新增实体手指或传感器延迟结论。

## 当前版性能

同一 release 二进制 SHA256 为 `824812d68d7f5c8c2c2d52a27d19fb56972a8eadb4a99bef76662fe222d0ff41`。端点往返性能窗口从新进程开始，只运行横向场景：按 10 秒预热、60 秒测量，窗口结束前完成当前手势，每六次改变方向，并记录实际手势数和时长。原生 MCP 的拖动按约 5 px 步进并等待 16 ms；本板移动中的完整大跨度手势实测约 4–5 秒。前两次按固定次数估算的有限进程在 155/150 秒正常退出时截断横向测量，均保留为不完整记录并排除；该负载的有效资源窗口为 `resources-final/`。

CPU/RSS 窗口关闭 trace、临时阶段计时、截图和事件录制，从进程外按约 1 秒间隔读取 `/proc/PID/stat`、`status` 及系统 uptime。CPU 以占满一个核心为 100%，时钟频率为已核验的 100 Hz。横向负载包含每次定位可见边缘卡片的原生 MCP 查询。

帧率在另一有限进程中用已有的低频 trace 统计，按成功完成 PAN 的整批 150 帧计数，丢弃跨场景起点的首批；不把该窗口的 CPU 值混入关闭 trace 的资源结果。

每六次换向的往返负载包含端点夹紧后的静止时间。其关闭 trace 的有效窗口约 60.85 秒、15 次手势，平均 CPU **79.28%**，RSS **13808–13980 KiB**（均值 13907 KiB），VmHWM 14308 KiB，3 个线程；MMZ 为 **12100 KiB / 5 块**。独立帧率窗口的 1200 次有效完成提交综合为 **22.84 FPS**，八批范围 10.90–28.71 FPS。

为区分移动和端点停留，另测边界前换向的持续运动负载。每次手势前后查询实际首项位置，要求移动超过 400 px 且结束位置不在任一边界。持续运动窗口约 61.58 秒、13 次测量手势，1650 次有效完成提交为 **28.64 FPS**，十一批范围 28.34–28.71 FPS。预热和测量记录中的滚动偏移为 93.44–3516.72 px，全部手势满足上述移动检查。这两个帧率代表不同负载，完整保留端点往返的较低综合值。

同一持续运动流程关闭 trace 后，约 61.57 秒内完成 13 次手势，平均 CPU 为 **85.43%**，RSS 为 **14136–14396 KiB**（均值 14357 KiB，约 14.0 MiB），VmHWM 14704 KiB，3 个线程，MMZ 仍为 12100 KiB / 5 块。CPU/内存与帧率使用相同流程、不同有限进程，避免低频统计影响资源指标。

上一版 `/tmp/slint-bridge-input-a0e880c/showcase`（`a0e880c`）及其脚本和日志保留回退；更早的 `/tmp/slint-bridge-clean-c087071/showcase`（`c087071`）也明确加入保留项，未清理。回退前重新核对设备、实际进程、静态页和提交线程状态；结束当前所有者并确认 VO 关闭、MMZ 回到基线和独占锁释放后，才运行恢复脚本。不能照抄观测 PID 或同时启动两个 SDK 显示程序。

63 个本轮诊断文件已校验归档后清理，三份程序及恢复文件都保留。收尾常驻 RSS 15388 KiB、VmHWM 15704 KiB、VmPeak 33716 KiB、3 个线程、MMZ 12100 KiB / 5 块，系统可用内存 34064 KiB。`/tmp` 使用 31376 KiB、剩余 14468 KiB，`/run` 使用 804 KiB；部署文件占用与上方独立资源窗口分开记录。

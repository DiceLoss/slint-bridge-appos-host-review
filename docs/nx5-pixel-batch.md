# NX5 Pixel 批量纹理混合

2026-10-15，将 NX5 TDE 软件回退使用的 `Pixel` 接入同源 Slint `5cfde5f` 的批量纹理混合。基线为桥接仓库 `9a4cdcc`，前后 Slint 提交、应用界面、构建路径、字体、SDK 和 `.cargo/nx5.toml` 均相同，仅改变 `Pixel` 的采样混合委托。

## 实现与验证方法

`Pixel` 是 `#[repr(transparent)]` 的 `PremultipliedRgbaColor` 包装。新增 `blend_sampled_slice` 将独占切片按相同布局转换后，直接调用 Slint 的实现；不复制目标画布、不增加堆分配，也不重复维护混合算法。原采样闭包仍按切片顺序每像素调用一次，Slint 每批最多收集 32 个源色，再执行精确整数混合或全不透明复制。

该方法只作用于未被 TDE 接受的软件纹理片段。已有单色 `blend_slice`、TDE 加速与失败处理、未知 DMA 隔离、双 framebuffer、单笔在途提交和单帧预渲染保持原逻辑。

正式 Cortex-A7 ARM ELF 的 NX5 `Buffer` 纹理循环，接入前没有对应向量混合指令；接入后包含 `vmull.u8`、`vadd.i16`、`vshr.u16`、`vsub.i16` 和 `vst4.8`。反汇编定位到 NX5 `Buffer::process_texture_impl` 的循环，未把软件截图目标或其它函数里的 NEON 当作此路径的证据。

新增库内测试直接调用 `Pixel::blend_sampled_slice`，以原单像素混合作独立参考，覆盖长度 0–65、四种起点偏移、alpha 0/1/127/254/255 及混合 alpha，检查采样次数、顺序、结果和切片两侧保护区，共 1584 组。主机 feature 矩阵、格式检查、`nx5-tde,slint/mcp` workspace / all-targets 严格 Clippy，以及原生 TDE 故障注入和像素边界检查通过。前后 showcase、候选 background-holes 和库测试的 ARM release 构建通过。

## 实机性能

设备为 NX5 / Linux `4.9.138 #233`，USB1 root、ADB `192.168.1.151:5555`，启动 ID `4aa4f5d2-8de2-42cb-9c2b-44c3e74d6e2b`。使用同一 1024×600、0°、`nx5-tde` 部署。每次切换先核对显示所有者、正常退出及 VO/MMZ 基线；测试开始时原常驻的信号退出单独记录，不当作正常析构结果。

每版本独立采集无 trace 的 CPU/RSS 和启用原有完成提交日志的 FPS。列表中段预热至少 8 秒，资源窗口至少 45 秒，FPS 动作窗口至少 60 秒；手势须超过视口 40%、避开端点、无轴漂移及误选。CPU 以单核 100% 为口径。FPS 仅使用完整的 150 次成功完成提交批次，丢弃跨阶段开始边界的首批；采样期间不截图或录制事件。

| 场景 | 优化前 → 后 FPS | 变化 | 优化前 → 后 CPU | 平均 RSS |
| --- | ---: | ---: | ---: | ---: |
| 富列表纵向 | 27.53 → 27.58 | +0.16% | 79.31% → 78.66% | 17.97 → 17.69 MiB |
| 富列表横向 | 25.81 → 26.13 | +1.25% | 86.28% → 86.08% | 18.23 → 18.02 MiB |

批量混合已进入正式 NX5 纹理循环，但本轮整机收益很小：纵向约增加 0.04 FPS，横向约增加 0.32 FPS；CPU 分别下降 0.64 / 0.20 个百分点。每版本每方向仅一个正式窗口，没有多轮统计显著性分析，不能把这些差异断言为稳定收益，也不能套用 X9 的加速比例。

正式资源窗口为优化前 45.57 / 47.51 秒、优化后 45.13 / 47.12 秒，纵横分别完成 26 / 8 次手势。四组 FPS 各使用 10 个完整批次，共 6,000 次成功完成提交。各资源窗口均为 3 线程，MMZ 12760 KiB / 6 块。两份 showcase 均为 10,805,632 字节。

首次基线资源采样另有纵向 70.54%、横向 85.79%，原始结果完整保留；纵向出现一次 3.36 秒的 ADB 读取延迟，45 秒窗口内仅完成 23 次手势，故另起进程重测两个方向，并以上表的同节奏重测作比较。正式前后资源采样的最大单次读取耗时分别为 0.086 / 0.083 秒；没有把首次较低 CPU 值隐藏或改写。

## 画面、功能与恢复

新增的 1584 组 `Pixel` 采样边界检查在 ARM release 测试程序上通过。另独占顺序运行六项硬件回归：

| 用例 | 本轮结果 |
| --- | --- |
| `neon_writeback_boundaries` | alpha 量程 128/255、全通道组合、短尾部、非对齐起点和保护区一致 |
| `nx5_hardware_compare` | 真实 TDE 复制/混合、奇数边缘、裁剪、缓存及软件回退通过；RGB 最大误差 1，预提交错误按预期回退 |
| `nx5_demo_pages_match_full_frames` | 100 帧真实 TDE 绘制与内存双页对照，超差通道 0；此项不写物理页 |
| `budgeted_shared_mmz_writeback_preserves_pixels` | 六帧、每帧 75 段，前台和源画布不变，完成后的物理页精确一致 |
| `shared_mmz_writeback_matches_staged_pixels` | 210 次物理提交，alpha 0/127/255、两种写页路径精确一致 |
| `blocking_flip_cadence` | 剔除 8 次预热后 120 次翻页均值 34.479 ms，29.003 FPS |

每项正常退出为 0，VO 关闭、MMZ 恢复 4900 KiB / 2 块。半透明共享 MMZ 转换写页均值 19.346 ms，只代表该阶段，不作为应用 FPS。

两版本分别重新采集富列表奇数位置的物理前台页：纵向首项 `(198,185)`、横向 `(197,186)`。使用实际 stride、页高度和稳定的前台偏移读取；前后两组 **1,228,800 像素逐字节一致**。四份物理页分别与原生软件截图比较，RGB 最大误差 1、超差像素 0，alpha 精确对应 NX5 `(a+1)/2`。

候选 showcase 的八页原生 MCP 交互及全部 18 张设备卡片的往返、边界和筛选通过，保存 19 张受内存检查保护的截图，截图前最低 MemAvailable 为 28848 KiB。表单、键盘、弹窗、动画暂停、透明开口、四档 PNG/SVG 缩放和富列表横纵拖动/选择通过；已查看缩放与列表截图。主体录制 743 条事件，横向每方向各 997 条事件，无丢失或未知事件。

真实 `/dev/input/event0` 注入两次点击、一次 12 步拖动，业务计数增加 2 / 1；记录 21 条事件，六个按下/释放边沿均 Accepted，坐标误差小于 1 像素，零丢失/未知事件。此项覆盖内核 evdev 到应用，不包含实体触摸传感器。

候选 `background-holes --verify` 的 23 个状态全部通过。45 张物理页共 **27,648,000 像素**，RGB 和 alpha 精确一致，前台逐阶段交替；故意损坏参考 alpha 的负对照被拒绝。插件只读取 framebuffer，不启动另一 SDK 会话，也不操作 WBC。验证程序正常退出并恢复 VO/MMZ 基线。

已恢复原 `background-holes`（Slint `fa6a6d0`），观测 PID **18345**；原 ELF、启动脚本和 `2fddc04` 恢复文件摘要均未变。两个区域为初始状态、Change 44、前景计数 0、弹窗关闭，完整 **614,400 像素**与测试前截图一致。当前仅该进程映射 SDK，无退出时限、trace、LD_PRELOAD、WBC 或检查插件。恢复后静态 RSS 11496 KiB、VmHWM 16300 KiB（含截图峰值）、3 线程、MMZ 12760 KiB / 6 块、可用内存 45092 KiB；这是恢复快照，不是采样均值。

原常驻停止后的整个测试窗口新增 153 条非空内核记录，无错误、OOM、超时或强制资源回收；以 1298 行连续重叠处理环形日志淘汰的 112 行旧记录，原始字节保留。最初旧常驻的信号退出单独记录，未混入正常退出判据。最后 69 个测试文件先逐文件 SHA256 校验归档后清理，当前程序、恢复文件和依赖保留。设备观测状态见 [当前快照](../test-app/devices/nx5/current-target.json)。

结论限定本轮 NX5 TDE / 0° 场景；静态物理页、MCP 和 evdev 注入分别解释，不代替 WBC、真实视频底层、实体触摸传感器或动态扫描验证。

# 纹理 NEON 优化后的 NX5 实机回归

2026-10-15，在 NX5 / Linux `4.9.138 #233` 上对 [Slint 纹理 NEON 优化](x9-texture-neon.md) 做同源应用的前后对照。本轮画面与功能检查通过，性能接近；已恢复任务开始时的原 `background-holes` 常驻程序。

## 版本与测量方法

设备重新核对为 USB1 root、ADB `192.168.1.151:5555`，MAC `f6:1e:04:4c:d8:78`，启动 ID `4aa4f5d2-8de2-42cb-9c2b-44c3e74d6e2b`。布局为 1024×600、0°、两张物理页。恢复程序和原常驻 ELF 在切换前核验并保留；测试期间每次切换都等待旧进程退出、VO 关闭及 MMZ 回到基线。

两份 `showcase` 均由桥接仓库 `1736f56` 的同一份临时源码构建，只切换同一路径下的 Slint 提交：`fa6a6d0158c9730fed62ef1eb1c9730c80214e20` → `5cfde5f2f2a9417373d4fd914730919327e935f8`。沿用 `.cargo/nx5.toml`、release、`arm-unknown-linux-gnueabi`、`nx5-tde,slint/mcp`、相同字体及 SDK；没有改动生产源码、固件、驱动或频率配置。临时路径只写入隔离副本的 Cargo 清单。

两个 showcase 均为 10,805,632 字节。每版本分别启动无 trace 的资源进程和仅启用原有提交日志的 FPS 进程，时限均为 180 秒。每轴在列表中段预热至少 8 秒；资源动作窗口至少 45 秒，FPS 动作窗口至少 60 秒。手势检查每次位移超过视口 40%、不触及端点、轴不漂移且不误选。测量期间不截图、录制输入或运行其他板端负载。

CPU 来自应用进程累计 ticks / 实际设备 uptime，采用单核 100% 口径；RSS 来自无 trace 进程。FPS 使用每 150 次成功完成提交的统计，排除跨开始边界的首批，以总帧数 / 总批次耗时汇总；不使用 UI ticks 或 TDE 调用次数。

## 性能结果

| 场景 | 优化前 → 后 FPS | 变化 | 优化前 → 后 CPU | 平均 RSS |
| --- | ---: | ---: | ---: | ---: |
| 富列表纵向 | 27.48 → 27.45 | -0.11% | 79.35% → 79.42% | 17.90 → 17.97 MiB |
| 富列表横向 | 25.88 → 25.77 | -0.41% | 86.11% → 86.26% | 18.16 → 18.23 MiB |

两方向本轮分别低约 0.03 / 0.10 FPS，CPU 分别增加 0.07 / 0.16 个百分点，平均 RSS 增加约 76 / 75 KiB。结果接近；本轮没有观察到明显性能退化，也未观察到 X9 那样的整机加速。每版本每方向只有一个有效长窗口，未做多轮统计显著性分析，不能把小幅差异断言为稳定损失或完全零影响。

资源有效窗口为优化前 45.23 / 47.36 秒、优化后 45.24 / 47.54 秒；FPS 动作窗口为 61.20 / 65.19 秒及 60.67 / 65.31 秒。纵向优化前使用 11 个完整批次，其余三组各 10 个，总计 6,150 次完成提交。各资源窗口均为 3 线程、MMZ 12760 KiB / 6 块，没有新增整帧画布或 MMZ 块。

NX5 的 [TDE 像素类型](../src/backends/nx5/tde/mod.rs) 是包装 `PremultipliedRgbaColor` 的 `Pixel`，连续混合加速针对单色 `blend_slice`，没有重写本次新增的 `blend_sampled_slice`，因此这条渲染路径继续使用默认逐像素混合。软件快照等使用 `PremultipliedRgbaColor` 的目标可以经过新批量实现。不能将 X9 的约 25%–28% 整机收益直接套用于当前 NX5 TDE 部署。

## ARM 与独占硬件验证

当前版本的 showcase、background-holes、库测试和公开纹理测试均交叉构建通过。`texture_blend` 的两项测试在 NX5 release ARM 程序上通过，覆盖四种旋转、24 个裁剪/背景状态共 294,912 像素，以及 131,072 组字节乘积、13 种 0–65 像素长度、四种起点偏移、透明/不透明批次、守卫和采样次数。

本轮另外逐项独占运行六项库内硬件回归：

| 用例 | 结果 |
| --- | --- |
| `neon_writeback_boundaries` | alpha 量程 128/255、全通道组合、长度 0–65、偏移 0–3 和保护区精确一致 |
| `nx5_hardware_compare` | 真实 TDE 复制/混合、透明度、源裁剪、奇数边缘、缓存和软件回退通过，RGB 最大误差 1；预提交错误注入按预期回退 |
| `nx5_demo_pages_match_full_frames` | 100 帧真实 TDE 绘制及内存双页对照，超差通道 0；此项不写物理页 |
| `budgeted_shared_mmz_writeback_preserves_pixels` | 六帧、每帧 75 段，前台和源画布不变，完成后的实际页精确一致 |
| `shared_mmz_writeback_matches_staged_pixels` | 210 次真实提交，0/127/255 三档 alpha；两种写页路径的采样页精确一致 |
| `blocking_flip_cadence` | 128 次翻页，剔除 8 次预热后均值 34.479 ms，29.003 FPS |

每项正常退出为 0，VO 关闭、MMZ 恢复 **4900 KiB / 2 块**。半透明共享 MMZ 转换写页均值 19.230 ms，仅为该阶段样本，不代替完整应用 FPS。

本次未修改 Rust 行为或构建配置，未重复整套主机检查；同一代码的 feature 矩阵、严格 Clippy 及主机纹理检查属于 [优化任务中已经完成的验证](x9-texture-neon.md#回归与可复跑入口)，与本轮新增的 NX5 实测分开记录。

## 画面与功能

前后版本均在本轮重新采集富列表两种奇数位置的完整物理前台页：纵向首项 `(198,185)`、pan `0,600`；横向首项 `(197,186)`、pan `0,0`。每次读取前后偏移稳定，均按实际 stride 和页高度读取。两组新旧页合计 **1,228,800 像素逐字节一致**；四次采样分别与同版本原生软件截图比较，RGB 最大差 1、超差像素 0，alpha 精确对应 NX5 `(a+1)/2`。

优化版通过完整八页原生 Slint MCP 检查，保存 19 张受内存检查保护的截图；截图前最低 MemAvailable 为 24232 KiB。表单、重置、触屏键盘、弹窗、动画暂停、透明开口、PNG/SVG 四档缩放、富列表横纵拖动和选择，以及普通设备列表全部 18 项的往返/边界/筛选均通过。主体录制 743 条事件，横向两个方向的分段录制各合计 997 条事件，均无丢失或未知事件。已查看缩放和富列表截图，布局、文字与透明合成正常。

随后通过真实 `/dev/input/event0` 注入 ABS_X/Y、BTN_TOUCH、SYN_REPORT：两次点击、一次 12 步拖动。业务计数增加 2 / 1，Slint 记录 21 条事件，三次接触的六个按下/释放边沿全部 Accepted，坐标误差小于 1 像素，零丢失/未知事件。此项验证内核 evdev 到应用处理，不包含实体触摸传感器。

优化版 `background-holes --verify` 的 23 个状态全部通过，包括区域移动、缩放、隐藏/恢复、跨区域前景和弹窗。45 张真实物理页共 **27,648,000 像素**，RGB 最大误差 0、alpha 精确一致，前台逐阶段交替；故意损坏一个参考 alpha 的负对照被拒绝。验证进程正常退出，VO/MMZ 回到基线。检查插件只读取 framebuffer，不加载另一份 SDK，也不操作 WBC。

## 恢复与范围

已恢复原 `background-holes`（Slint `fa6a6d0`），观测 PID **26898**，原 ELF 与启动脚本均未改变；保留原 `2fddc04` showcase 恢复文件。两个区域位于初始位置，Change 44、前景按钮计数 0、弹窗关闭。恢复操作最初留下 Reset 悬停，差异限定在该按钮且 alpha 无差异；用原生 `move_pointer` 清除后，完整 **614,400 像素**与本轮测试前截图逐字节一致，两次截图均保留。

当前无退出时限、trace、LD_PRELOAD、WBC 或检查插件；仅原常驻进程映射 SDK，三个线程分别为主线程、`fb-present`、`async-io`。常驻 RSS 11380 KiB、VmHWM 16188 KiB（含截图峰值）、MMZ 12760 KiB / 6 块、可用内存 44792 KiB。这是恢复后的静态快照，不是性能窗口均值。当前路径、观测时间及恢复前提见 [设备快照](../test-app/devices/nx5/current-target.json)。

六项硬件测试及六个有限应用进程均正常退出，资源恢复基线。原常驻停止后的测试窗口新增 140 条非空内核记录，没有 OOM、错误、超时或强制 MMZ/VO 回收。内核环形日志淘汰了 32 条旧记录，分析用 1267 行连续重叠定位全部新日志；未将最初停止旧常驻时的信号退出回收计入有限测试结果，也没有修改原始日志。

所有非活动候选与测试文件均先逐文件 SHA256 验证归档；最后一轮清理 64 个文件，当前及恢复程序、依赖和活动日志保留。首次最终清理因保留策略中的新日志尚未创建而在预检查阶段拒绝，没有发出删除计划；控制目录经 `discard` 归档，原常驻启动后使用全新清单成功清理。最初输入工具向保留目录上传的尝试也在传输前被拒绝，随后使用新的测试目录。隔离构建的临时 Slint worktree 已移除，主源码及原有未跟踪文件保持原样。

本轮不声称新增 WBC、非黑色视频底层、实体手指、动态逐扫描帧或 NX5 90°/270° 上屏验证。ARM 离屏旋转回归、原生 MCP、实际页及 evdev 各按自己的覆盖范围解释；静态页一致不替代动态扫描无撕裂证明。

原始证据保存在本地忽略目录 `evidence/nx5-texture-neon/2026-10-15/`，检出仓库需另行取得。包含构建日志及清单、`binaries.json`、两版本四个性能窗口的原始 `/proc` 样本/手势/完成日志、两组新旧物理页与截图、硬件测试日志及资源快照、UI 和输入记录，以及逐文件 SHA256 校验的部署清理档案。板端控制目录也按部署工具流程归档。复跑构建入口见 [设备说明](../test-app/devices/nx5/README.md)，部署、截图和背景双页校验入口见 [NX5 工具说明](../test-app/tools/nx5/README.md)。

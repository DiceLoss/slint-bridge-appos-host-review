# NX5 显示完成与合成验证

本篇合并显示驱动、双周期翻页、SDK/WBC 生命周期与 alpha 量程的调查结论。#22 与 #233 是不同验证对象，以下结果不能跨固件混用。现行运行约束以 [平台说明](software-platform.md#准入边界) 为准；操作方法见 [NX5 设备说明](../test-app/devices/nx5/README.md) 和 [工具说明](../test-app/tools/nx5/README.md)。

原始 `evidence/` 为本地档案，不随 Git 分发。本文中的版本、时钟和地址属于对应采集阶段，不能用作设备实时状态或未知固件的准入依据。

<a id="nx5-present-validation"></a>

## 早期固件验证的边界

2026-10-10，Linux 4.9.138 #22、1024×600、当时 SDK 摘要 `8064b9d…331bd82`。阻塞 PUT 返回约 1 微秒后覆写旧页的两组测试，各有 64 次翻页、85 个 WBC 样本，未检出异常；故意提前写活动页的负对照在 21 帧中检出 11 个异常。

**该阶段未通过无撕裂准入。** WBC 实测约 30.08 FPS，不能覆盖标称 60 Hz 的全部输出帧，也没有证明最后一次旧页 DMA 读取结束。128 次无 WBC 的 ioctl 平均 24.742 ms，只是调用耗时。地址进入寄存器早于更新位清零，页号或地址读回都不能独立证明旧页退休。

`--require-admission` 返回 2 是该证据集的预期结果。后续 #233 的采用及固定摘要门禁移除，不改变 #22 的认证缺口。证据：`evidence/nx5-present/`，包括 `observations.json`、`device-run/` 和 `run-manifest.json`。

<a id="nx5-display"></a>

## 软件上屏与 SDK 会话

2026-10-10，#233 软件渲染阶段，尚未接入 TDE，使用当时的 PUT 和限帧配置。黑白整帧取得 300 个 WBC 样本，黑白各 150、混色 0；混色负对照 30/30 被检出。采样和稳态提交约 29 FPS。这是有限合成输出观测，不是全部 LCD 扫描帧的认证。

独立采集进程首次加载 SDK 曾重置运行中的 SYS/VO；改为进程内采集后，错误调用 `FY_MPI_VO_CloseFd()` 又关闭了显示共用句柄，造成不可中断等待并需要重启恢复。由此确立：WBC 只复用显示会话，释放取得的帧并关闭 WBC，不关闭共用 VO；应用退出要等待观察线程完成。第二个显示实例应在加载 SDK 前被拒绝。

早期逐字节 framebuffer 写入改为对齐存储后，写页均值约 24.3 → 4.4 ms，界面约 18 → 29 FPS；这不是后续 TDE、NEON 或富列表成绩。全像素读取未缓存 WBC 内存的 7.24 FPS 慢采集未纳入通过样本。证据：`evidence/nx5-display/`，保留正常、负对照、外部采集重置和驱动等待失败记录。

<a id="nx5-flip"></a>

## 双周期翻页与约 29 FPS 节拍

#233 匹配模块的实际时序为 1344×635，像素时钟选中 49.5 MHz。计算刷新率为 58.00056 Hz，中断实测 57.9986 次/秒；`DevFrt=60` 和 LCM 标称值不等于实测刷新率。

| 时序 | 水平 | 垂直 |
| --- | ---: | ---: |
| 有效区域 | 1024 | 600 |
| 前肩 / 同步 / 后肩 | 160 / 1 / 159 | 12 / 1 / 22 |
| 总计 | 1344 | 635 |

`fyfb_fb_pan_display()` 消耗旧信号、提交 surface，再等待 `fyfb_notify()`。约第一次刷新时地址更新并置 `update_rdy`；约第二次刷新时更新位清零，PAN 返回。相位扫描 256 次翻页均成功：0–17 ms 准备时间对应约 34.482 ms，17.5–31.5 ms 对应约 51.723 ms；无准备吞吐 29.00022 FPS。

当前自定义 ioctl 没有有效 VSYNC 等待语义。改变提交相位、页号读回、一次 VSYNC 或固定睡眠都不能替代完成契约。若保持双周期而要到 30 FPS，需要 BSP 验证真正的 60 Hz 时序：例如匹配 51.2064 MHz 时钟，或依据面板规格调整消隐。直接切到 56.25 MHz 会得到约 65.91 Hz，不能当作修复。

证据：`evidence/nx5-flip/`，包括 `driver-tables.json`、`clock-readback.txt`、`precise.log` 和 `results.json`。这些寄存器解释只对应所核对模块。

<a id="nx5-single-cycle"></a>

## 单周期路径仍未实现

同一 #233 固件的 128 次提交进一步分为“等待刷新回调处理提交队列”和“等待下一次硬件锁存完成”。每次新页待锁存时，旧页仍是驱动当前页；完成通知没有可直接删掉的整周期尾部等待。

| 指标 | 当轮结果 |
| --- | ---: |
| 连续完成间隔 | 34.48239 ms |
| 纯翻页吞吐 | 29.00031 FPS |
| 提交到首次观测待锁存新页 | 平均 17.640 ms |
| 待锁存到首次观测当前页切换 | 平均 17.169 ms |
| 新页待锁存时旧页仍为当前页 | 128 / 128 |

以至少 55 FPS 检查单周期目标时明确失败。用户态采样有延迟，不能把这些时间当作精确锁存时刻；初版非缓存别名读取内核 RAM 的旧字段已作废，最终使用缓存视图。

真正单周期需要驱动提前准备 GUI 提交，同时保留锁存后的请求对应完成通知、旧页引用及错误传播；需要匹配源码或可审查实现和硬件语义。当前没有部署这种驱动改动。不得通过更多在途提交、提前写旧页或 MMIO 旁路取得“通过”。证据：`evidence/nx5-single-cycle/` 的 `stages.log`、`results.json`、`negative-replay.json` 和作废的 `stages-uncached-invalid.log`。

```sh
# 需要先取得相应本地档案；以下是证据重放，不是新实测。
python3 test-app/tools/nx5/flip/analyze.py evidence/nx5-flip
python3 test-app/tools/nx5/single-cycle/analyze.py evidence/nx5-single-cycle/stages.log
# 此门槛应失败，不能改为降低验收标准。
python3 test-app/tools/nx5/single-cycle/analyze.py evidence/nx5-single-cycle/stages.log --min-fps 55
```

<a id="nx5-alpha"></a>

## 透明合成量程修复

2026-10-12，`287da8c` 在纯软件和 TDE 两条路径的 framebuffer 字节比较都通过，但黑底 WBC 色块最大 Y/UV 差为 74。alpha=127 已接近全不透明，证明物理页字节正确不等于合成正确。

修复版 `f963558` 保持画布/TDE 的 0–255 预乘 RGBA，只在 NX5 写页时将 alpha 编码为 `(a+1)/2`，RGB 按原 alpha 精确反预乘。没有改 VO 全局 alpha 或放宽阈值；通用设备仍使用自身契约。

| 修复后检查 | 纯软件 | nx5-tde |
| --- | --- | --- |
| 五幅实际前台页 | 3,072,000 像素、错误 0 | 3,072,000 像素、错误 0 |
| WBC 样本 / 配对采样点 | 25 帧 / 15,000 对 | 25 帧 / 15,000 对 |
| 最大 Y/UV 差 | 1 | 1 |
| 全透明阶段 | 黑色输出，差异 0 | 黑色输出，差异 0 |
| 正常退出 | VO/WBC 关闭，MMZ 4900 KiB / 2 块 | 同左 |

色块本身未发起 TDE 纹理作业；另有 60 秒纹理运行覆盖硬件复制/混合，稳定批次均为 29.00 FPS。上述验证是静态阶段和交替页，不证明非黑色视频底层或连续运动的每个扫描帧。

基线实体触摸为 12 次接触、49 条 Accepted 事件，分派时间保守上界约 11.3 ms；修复版只获得用户四次点触的正常反馈及另行 MCP 回归，没有把基线时延改记为修复版测量。证据：`evidence/nx5-alpha-deploy/2026-10-12-287da8c/`，包含原始失败和修复记录。

<a id="slint-nx5-lessons"></a>

## 保留的历史实现教训

2026-10-12 对旧 `slint-nx5` 仓库的调查覆盖到 `d247651`，并在本项目 `287da8c` 阶段吸收部分改进。旧实现和规格不作为当前接口规范：

- 页号、SDK 提交返回和 DMA 完成是不同事件；未知完成状态必须保留 MMZ、SDK 会话及独占锁。
- 输入只在完整 `SYN_REPORT` 分派，不能把“本条事件没有输出”当成队列为空，也不能按事件类型重排跨接触边沿。当前协议范围见平台说明。
- 画布预乘、写页反预乘、显示 alpha 量程必须分别验证；当时保留 0–255 显示 alpha 的方案后来被上述 WBC 实测纠正。
- 两槽命中时刷新替换次序的主机回归，使八帧固定背景上传由 4 次降为 1 次、总上传量由 5,242,880 降为 2,883,584 字节；这是替身计数，不是设备 FPS。
- MMZ 释放失败后禁止再次创建 TDE，避免地址重复释放或不确定分配累积。旧 JPEG 功能没有因此引入当前项目。

旧仓库的 9 项 framebuffer 主机测试、TDE/VGS 替身及 6 轮历史 ACK 重放通过；本项目当轮主机与 ARM CPU 替身也通过，但不等于新增真实 DMA 故障或视频合成验证。证据：`evidence/slint-nx5-lessons/2026-10-12/`。

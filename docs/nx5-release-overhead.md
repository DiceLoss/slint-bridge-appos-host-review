# NX5 新旧正式版资源对照

2026-10-14，在同一 NX5 #233 上直接运行已部署的旧版 `c087071` 与新版 `a0e880c`，核对约 1 ms 分段写页后的正式应用开销。没有重建或修改二进制、界面、SDK、驱动或 Slint；两版测试应用的 Rust/UI 源码相同，Slint 均为 `22804ff`。

## 版本与方法

| 版本 | 设备文件 | SHA256 |
| --- | --- | --- |
| 旧版 | `/tmp/slint-bridge-clean-c087071/showcase` | `729f5088bc670c74ddef6fa002d69859fd67e692e351286ae219ee5bc3c81b7f` |
| 新版 | `/tmp/slint-bridge-input-a0e880c/showcase` | `71582ca6f70b8ab5aec9b0408b43429743bf5cb7491486cd6da09bed837fd584` |

CPU/内存按 **旧→新→新→旧** 执行，每轮从新进程开始，参数、字体、SDK、页面顺序和自动手势相同。四轮均关闭 trace、临时阶段计时、WBC、截图和事件录制；应用环境记录与二进制摘要已保存。用 Slint 原生 MCP 执行以下场景：

- Controls 静态页：预热 3 秒，测量 10 秒。保留正式应用的定时器和 MCP 服务，属于静态界面窗口。
- Motion 动画：预热 8 秒，测量 30 秒。
- Devices 列表：预热 12 次拖动，测量 36 次，按六次向上、六次向下循环。
- Layers 透明滑块：预热 12 次拖动，测量 36 次，交替拖向两端。

资源从进程外每秒读取 `/proc/PID/stat`、`status`、系统 uptime 和内存信息，不加载 SDK。CPU 为进程 `utime + stime` 增量除以实测区间与时钟频率，**占满一个 CPU 核心为 100%**；通过设备 `AT_CLKTCK` 确认 100 Hz。RSS 使用各窗口采样均值，另保存 VmHWM 和 MMZ 分配。设备未提供所检查的 cpufreq 接口，因此采用相邻且反向重复的运行顺序控制时间漂移。

帧率另开两轮，使用同一正式二进制已有的 `SLINT_BRIDGE_TRACE=1` 低频统计。只统计成功完成 PAN 的整批 150 帧，丢弃跨越场景起点的首批；这一轮的 CPU/RSS 不混入上面的资源结果。它没有重新加入已删除的临时阶段计时代码，也不把 UI 定时器 tick 当成显示 FPS。

收尾恢复新版原启动脚本，观测 PID **13408**，无退出定时器，trace、临时计时、WBC 和事件录制关闭，Controls 为 48%。日志为 `/tmp/slint-bridge-input-a0e880c/live-after-release-ab.log`；原 `c087071` 程序和启动脚本继续保留回退。收尾 RSS 14860 KiB、VmHWM 15208 KiB、VmPeak 33608 KiB、3 个线程，系统可用内存 44528 KiB。55 个测试及旧活动日志文件已校验归档后清理；`/tmp` 使用 21168 KiB、剩余 24676 KiB，`/run` 使用 804 KiB。

## 证据与范围

原始证据在本地 `evidence/nx5-release-overhead/2026-10-14/`，被 Git 忽略，检出仓库后需另行取得。`manifest.json` 保存身份、版本和方法；`old-1/`、`new-1/`、`new-2/`、`old-2/` 保存资源样本、环境和正常退出记录；`old-fps/`、`new-fps/` 保存独立帧率窗口；`compare.py`、`finish.py`、`analyze.py` 是该轮归档的主机脚本，`results.json` 汇总结果。

本轮是正式 `showcase` 的自动交互对照，与[输入延迟报告](nx5-input-latency.md)中的临时整屏 alpha=127 压力应用不同。不能把此前带阶段计时的 CPU 增幅全部归因为计时开销，也不能把这里的结果直接推广到所有应用。本轮没有新增实体手指、WBC、物理页像素或 LCD 扫描验证；已有验证保留各自报告的范围。当前程序与恢复前提见[设备说明](../test-app/devices/nx5/README.md)。

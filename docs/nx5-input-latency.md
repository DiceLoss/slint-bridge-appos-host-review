# NX5 输入延迟与分段写页

2026-10-13 开始、14 日收尾，基于清理版 `c087071`（仓库基线 `01a8208`）、Slint `22804ff`，在同一 NX5 #233 上检查渲染和 framebuffer 写入对输入的阻塞，实现提交为 `a0e880c`。本轮按用户要求采用自动对照，没有新增手指触摸样本，也没有修改固件、SDK、驱动或外部 Slint。

## 诊断与实现

原始事件循环在同一次迭代中可以连续渲染和整页写入。回归让 evdev 管道事件在实际 Slint 渲染回调内到达：修改前，Slint 点击回调执行时后台页已经写入；修改后先分派输入。该回归已在主机和 NX5 ARM 上通过。

展示应用 Motion 场景的基线平均渲染约 27.2 ms、写页约 2.7 ms；切页时单次渲染曾超过 50 ms。稳态预渲染原本就经常与上一帧 PAN 并行，因此只在渲染后返回循环的初步版本，普通场景尾部改善仅约 1–2 ms，没有把它记为整体延迟大幅下降。

最终实现还将 CPU 写页分段执行，运行时预算约 1 ms，每约 8192 像素对应的完整行检查时间。每段返回后重新处理输入和任务；保留画布冻结，整页完成才提交。没有增加画布、物理页或 MMZ 块，仍最多一笔在途提交和一帧预渲染。取消部分写入时保留脏区并使后台页重新初始化，后续两页均能修复。当前行为集中在 [平台说明](software-platform.md)，时序见 [运行图](diagrams/runtime-sequence.html)。

单次 Slint 渲染、布局和业务回调仍同步占用 UI 线程；本轮没有在渲染内部重入 Slint。1 ms 是写页让出的软预算，不是所有输入的硬实时上限。

## 自动对照方法

使用真实显示进程、SDK、共享 MMZ 和双 framebuffer。场景由 Slint 原生 MCP 设置并录制事件；独立回放器通过 [Linux evdev 写入接口](https://raw.githubusercontent.com/torvalds/linux/v4.9/drivers/input/evdev.c) 发送 ABS_X/Y、BTN_TOUCH 和 SYN_REPORT，只读观察器保存内核时间戳。回放器不加载 SDK、不操作 framebuffer，结束时释放接触。比较内核报告到 Slint 完成分派的时间，包括回调耗时；不包含传感器感应和 LCD 扫描延迟。

初轮移动间隔实测约 40 ms，而此前实体拖动档案的中位间隔为 7.165 ms；后续改用约 10 ms 的自动间隔。各场景短窗口分别录制，检查接触数、事件顺序、坐标、丢失及未知事件。没有把慢回放的近零延迟当作高频拖动结果。

整屏半透明诊断应用通过库公开 API 运行，背景以 33 ms 定时器在两种 alpha=127 的颜色间切换，触摸更新计数。两版使用相同的 16 次拖动、每次 24 个移动点，共配对 416 条按下/移动/松开事件；计入 PointerExited 后为 432 条，均 Accepted、无丢失或未知事件。

诊断构建在内存中暂存阶段时间，正常退出时再输出，避免逐帧日志 I/O 干扰；临时计时及诊断应用源码已移出维护中的代码。一次重复固定坐标的记录因观察器缺少初始轴值被拒绝，原档保留。观察器现将 ioctl 查询的初始 X/Y 写入就绪行，分析器已有对应回归；有效重测独立保存。

## 整屏半透明结果

| 指标 | 原始调度 | 分段写页 |
| --- | ---: | ---: |
| 全部输入分派延迟 P95 | 16.88 ms | 0.86 ms |
| 全部输入分派延迟最大值 | 18.94 ms | 2.86 ms |
| 按下/松开边沿 P95 | 18.74 ms | 0.85 ms |
| 单次连续写页占用均值 | 19.59 ms（整页） | 1.05 ms（一段） |
| 单次连续写页占用 P95 | 19.88 ms | 1.20 ms |
| 渲染均值 | 3.40 ms | 3.42 ms |
| 稳态完成提交帧率 | 约 19.3 FPS | 约 19.3 FPS |

MCP 时间戳精度为 1 ms，表中小数是与内核微秒时间戳相减的观测值；保守判读可加 1 ms，少量负小数属于量化误差。整帧各写段耗时合计约 20.03 ms（原 19.59 ms），包含段间输入处理的首段至末段时间约 20.98 ms；优化减少的是连续阻塞。该约 19.3 FPS 属于整屏半透明压力负载，不能替换展示应用或历史整屏场景的帧率。

## 正确性与范围

- 主机回归覆盖渲染中到达的输入、预算到期后的写页进度、部分页不提交、画布冻结、取消写入及随后两页脏区修复。feature 矩阵、格式、严格 Clippy 与 ARM 构建通过。
- 最终代码的物理写页测试交替呈现六帧 alpha 0/127/255，每帧以零预算强制分成 75 段；3686400 个实际页像素完全匹配，每帧首段后的前台页读回未变，完整帧后的源画布检查通过。
- 100 帧真实 TDE 与内存双页对照使用预算写页，最大通道误差 1；这是内存页比较，与上方物理页检查分开记录。
- 两项 SDK 测试正常退出后 VO 关闭，MMZ 回到 4900 KiB / 2 块，显示锁释放；同次内核窗口没有新增 MMZ 强制回收。

原始证据位于本地 `evidence/nx5-input-latency/2026-10-13/`：`baseline-02/`、`checkpoint/` 保存早期阶段试验；`baseline-fast/` 保存高频基线；`checkpoint-fast/` 的最后切页窗口因定时退出不完整，不作为完整对照；`alpha-baseline/`、`alpha-sliced-02/` 是表中有效半透明对照；`hardware-final/` 保存真实页和 ARM 回归。该目录被 Git 忽略，检出仓库后需另行取得。当前部署与回退以 [设备记录](../test-app/devices/nx5/README.md) 为准。

## 最终展示应用

无临时计时代码的 `a0e880c` 完成六页交互、10 张原生 MCP 截图和 227 条自动事件检查。另一轮从新进程开始的自动 evdev 回放共 112 次接触，1104 条 Slint 事件全部 Accepted，无丢失或未知事件。以下包含全部按下、移动和松开事件；这不是手指感应或 LCD 扫描测量。

| 场景 | 原始高频基线 P95 | 最终版本 P95 |
| --- | ---: | ---: |
| Motion | 25.84 ms | 24.87 ms |
| Devices 拖动 | 21.87 ms | 21.88 ms |
| Layers 滑块 | 10.86 ms | 10.82 ms |
| 切页 | 28.85 ms | 33.85 ms |

普通展示场景仍受单次渲染、布局和回调限制，本轮未证实其整体尾延迟改善；最终滑块窗口最大样本约 44.88 ms，记录保留。不能把半透明压力负载的改善推广到全部界面。基线为有阶段计时的诊断构建，最终展示版已经移除该计时，两轮样本也不是逐事件相位配对。

独立列表帧率窗口预热 8 秒、测量 35.7 秒，43 次原生 MCP 拖动，六批各 150 次成功提交均为 29 FPS；测量期间不截图、不录制事件。最终界面用例和性能用例均正常退出，VO 关闭、MMZ 回到 4900 KiB / 2 块。证据分别为 `final-ui/`、`final-showcase/`、`final-list/` 和 `final-finite/`。

# NX5 快速填充与整体透明度混合

2026-10-13，同一 NX5 #233、1024×600、Cortex-A7/NEON、Slint `22804ff`，接入 QuickFill 和等尺寸 RGBA 图像的整体透明度，并核查 TDE 成功后是否仍执行同一操作的软件绘制。设备启动 ID 为 `938c34d4-456a-4b1a-b532-678c0f92efd0`。SDK、驱动、双页完成契约和提交调度未修改。

结论：已验证的 TDE 成功操作后，软件绘制行访问为 **0**；回退用例没有硬件提交。纯色填充在本面板范围内未发现 TDE 更快的面积交叉点，默认继续用 CPU，QuickFill 保留显式对照开关。整体透明度图像混合默认支持，512×384 缓存命中时约为软件的 2.3–3.0 倍。

## 同一操作是否被两条路径重复绘制

检查位置为 `TargetPixelBuffer` 回调与 Slint 软件 renderer 的交界。Slint 的 `process_target_texture()` 在 `draw_texture()` 返回 `true` 时立即返回，只有 `false` 才进入软件逐行绘制。矩形和窗口背景有相同的处理约定。

新增 `DispatchAudit` 包装生产 `Buffer`，使用仅含窗口背景、图像和矩形的受控 Slint 场景。分别记录每种操作的回调结果，以及回调之后访问 CPU `line_slice()` 的次数；计数器不改写回调结果。实机使用真实 SDK 和 TDE，像素仍与独立软件结果逐一比较。

| 操作 | TDE 成功次数 | 同一操作后软件绘制行数 |
| --- | ---: | ---: |
| QuickFill 背景，alpha 0 / 1 / 127 / 255 | 各 1 | 各 0 |
| 不透明图像复制 | 1 | 0 |
| straight / premultiplied RGBA 混合 | 各 1 | 各 0 |
| 负坐标裁剪混合 | 1 | 0 |
| 50% 整体透明度混合 | 1 | 0 |
| 奇数坐标混合回退 | 0 | 383 |
| 缩放图像回退 | 0 | 192 |

同一帧的其他操作可以使用软件。例如图像进入 TDE 时，窗口背景仍由 CPU 清除 384 行、小矩形仍由 CPU 绘制 19 行；它们有独立的操作计数，不能算成该图像的软件重绘。主机还用明显不同于源图片的哨兵像素检查：模拟硬件返回成功后，哨兵保持；返回未处理后，软件才绘制源图。原始结果为 `dispatch.log`。

TDE 路径中仍有 CPU 工作：准备/预乘源像素、缓存同步、把已完成的 MMZ 结果拷回保留画布，再进行 framebuffer 格式转换。这些步骤不再次执行 Slint 图像合成，但会占用 CPU 和内存带宽。此次没有取消这些完成与一致性步骤。

## 填充面积和形状阶梯

使用真实 1024×600 画布、4096 字节行跨度、同一 CPU 输出布局。每组先预热十对，再交替执行 CPU/TDE 各 60 次，分别测试透明零色与非零不透明色，共 **22 组**。每组比较完整画布，包含区域外保护；全部逐字节一致。

TDE 计时覆盖私有 MMZ 的缓存同步、QuickFill 提交、阻塞完成确认、结果回拷；CPU 计时为相同行范围的批量填充。排除 framebuffer 翻页。以下为不透明色平均耗时，透明零色结果接近；完整平均数、P50 和 P95 保存在 `fill-area.json`。

| 区域 | 像素数 | CPU | TDE |
| --- | ---: | ---: | ---: |
| 16×16 | 256 | 0.005 ms | 0.321 ms |
| 64×64 | 4096 | 0.036 ms | 0.477 ms |
| 128×128 | 16384 | 0.125 ms | 0.736 ms |
| 1024×32 | 32768 | 0.092 ms | 0.714 ms |
| 128×256 | 32768 | 0.252 ms | 1.170 ms |
| 256×256 | 65536 | 0.380 ms | 1.616 ms |
| 上下分离的两条 1024×32 | 65536 | 0.186 ms | 2.102 ms |
| 1024×128 | 131072 | 0.365 ms | 2.283 ms |
| 512×384 | 196608 | 0.826 ms | 3.567 ms |
| 1024×300 | 307200 | 0.855 ms | 4.794 ms |
| 1024×600 | 614400 | 1.710 ms | 9.344 ms |

本面板内全部测量点均为 CPU 更快。形状和行跨度也影响结果：相同 32768 像素的长条/窄高区域耗时不同；当前 TDE 按涉及行的首尾范围同步缓存，分离矩形还会包含中间行。不能仅按有效像素面积推出通用阈值，也不能把此完整集成路径的结果等同于裸硬件填充吞吐。

因此 `SLINT_BRIDGE_TDE_FILL=1` 显式启用 QuickFill，默认使用 CPU。生产对照入口仍限定不少于 32768 像素、最多 16 个裁剪矩形；面积测试直接调用原生加速器，包含该阈值以下的区域。其他芯片、布局或不同内存所有权设计不在本轮结论范围内。

## 图像整体透明度

普通 RGBA 先按 `floor(pixel_alpha × opacity / 255)` 合并 alpha，再预乘 RGB；预乘 RGBA 直接对四个通道应用 opacity。Cortex-A7 用 NEON，标量路径使用相同整数规则。缓存键包含图像身份和 opacity，只有两者不变才复用准备好的源像素。

首次直接使用 SDK 全局 alpha 产生最大 114/255 的色差，失败日志 `compare-01.log` 保留。现不使用该 SDK 开关，由源准备路径保持 Slint 的运算顺序。第二轮新增极低 opacity 断言发现 Slint 会在 `opacity <= 0.01` 时直接剔除图像；修正的是“必须发生硬件回调”的错误测试假设，未更改 renderer 剔除行为。最终所有格式、边界档位、缓存重用与裁剪检查通过，单次混合 RGB 最大差 **1/255**，alpha 与参考一致。

最终 `dispatch.log` 中，512×384、预热后 60 帧、整体 opacity=50% 的平均值如下，含渲染/提交/同步/回拷，不含 framebuffer 翻页：

| 图像来源 | 软件 | TDE | 比值 |
| --- | ---: | ---: | ---: |
| 不透明 RGBA + 50% opacity | 32.842 ms | 11.143 ms | 2.95× |
| straight RGBA + 50% opacity | 33.147 ms | 11.139 ms | 2.98× |
| premultiplied RGBA + 50% opacity | 25.615 ms | 11.146 ms | 2.30× |

这是同一透明度下源缓存命中的成绩；每帧改变透明度会重新准备/上传，未把缓存命中倍率作为该情况的保证。缩放、旋转、透明目标及不满足对齐/面积限制的图像继续软件回退。展示应用的图片背景此前已经 QuickCopy；当前 Media 叠加图仍从 192 缩放到 190 像素，仍为软件绘制，未靠改 UI 尺寸制造硬件命中。

## 验证与复跑

- 主机 feature 矩阵、格式、严格 Clippy 通过。新增回归覆盖 opacity 缓存、填充裁剪/语义回退、已知失败与未知 DMA 的不同处理，以及成功回调不再软件重绘。
- C 的 ASan/UBSan 替身测试覆盖复制、混合、填充的 Begin/绘制/Cancel/End/同步失败；失败不提交部分 CPU 像素，完成未知时保留资源。还覆盖源准备所有 alpha 组合、长度 0–65、非对齐地址及边界。未在板上制造真实 DMA 挂死。
- `nx5_hardware_compare`：实际 SDK 的填充、复制、整体透明度、裁剪、stride、写时复制、回退、80 帧增量运动与调用链计数通过。
- `nx5_demo_pages_match_full_frames`：开启 QuickFill，100 个交替内存页使用真实 TDE 绘制并与独立软件参考比较，最大通道差 1，无超差通道。此项不冒充物理 LCD 页采集。
- `nx5_fill_area_crossover`：22 组真实 TDE 面积/形状/颜色对照通过，正常退出后 MMZ 回到 4900 KiB / 2 块，VO 和独占锁释放。本轮未重测阻塞翻页节拍、WBC、视频层或实体触摸时延。

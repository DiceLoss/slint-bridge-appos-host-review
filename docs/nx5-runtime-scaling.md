# NX5 PNG / SVG 运行时缩放测试

2026-10-14，展示应用代码 `abb2e33`，Slint `22804ff`。新增独立第七页 **Image scaling**，PNG 和 SVG 并排显示，滑块范围 50%–200%，步长 1%，按钮恢复 100%。原 Layers 页保持原样，库运行时、SDK、驱动及外部 Slint 未修改。

## 缩放发生在运行时

两份源资源均为 256×160，包含四色象限、透明外边、白色交叉线和半透明圆形。PNG 由同一 SVG 在原始尺寸生成；没有生成多档缩放资源。应用启动时通过 `Image::load_from_data` 和 `Image::load_from_svg_data` 加载原始编码字节，滑块改变 `.slint` 中 Image 的目标宽高。SVG 保留矢量数据，由软件 renderer 按目标尺寸栅格化；PNG 保持原位图并在绘制时缩放。本页没有使用 Slint 编译期图片尺寸优化，原海岸背景的构建处理不受影响。

NX5 上 50%、100%、125%、200% 对应目标尺寸 128×80、256×160、320×200、512×320。两个固定预览窗约 370×203，放大后居中裁剪。实现入口为 [scaling.slint](../test-app/ui/showcase/scaling.slint)、[应用加载代码](../test-app/src/showcase.rs)，使用方法见[测试工程说明](../test-app/README.md#六页展示应用-showcase)。

## 验证方法

主机回归在同一保留缓冲上依次运行 50→100→125→200→125→50→100%，每档与独立新窗口的全量重绘比较，累计 **1420342 个像素完全一致**，覆盖缩小后旧区域清除。另检查源图始终为 256×160，并按像素测量四色图案中的红色区域随比例改变；该结果是主机软件画布测试。

维护中的原生 MCP 用例检查四档目标几何、四色中心像素、透明角落及 200% 的四边裁剪，包含实际滑块拖动和 100% 按钮复位。完整用例覆盖七页、17 张截图，同时保留原有横向列表回归。主机 feature 矩阵、格式、严格 Clippy、四项性能分析器回归及 ARM release 构建均通过。

NX5 同一 release 文件通过上述七页、17 张原生截图及横向列表用例；主录制 291 条事件，14 个横向短窗口合计 1994 条事件，dropped/unknown 均为 0。四档缩放截图已逐张检查布局。MCP 截图是 UI 重绘结果，不等同于 framebuffer 或 LCD 扫描读回；本轮不新增物理页、WBC、自动 evdev 或实体手指结论。

## 当前版性能与收尾

两次独立有限进程都只测本页，先预热约 8 秒，再测量至少 45 秒并完成最后一次手势。原生 MCP 交替向滑块两端拖动；PNG 与 SVG 同时改变尺寸，结果代表组合场景，不能拆分为单一格式开销。资源窗口关闭 trace、截图和事件录制，从进程外约每秒读取 stat/status/uptime，CPU 以单核占满为 100%。

资源窗口约 46.20 秒、24 次拖动：CPU **88.35%**，RSS **15488–15612 KiB**，均值 15491 KiB，VmHWM 16132 KiB，3 线程。独立低频 trace 窗口约 46.27 秒、24 次拖动，按完整的 150 帧批次并丢弃跨起点批次统计，900 次成功完成提交为 **25.87 FPS**；这不是 UI timer 计数或端到端触摸延迟。两轮运行时 MMZ 均为 12100 KiB / 5 块。

UI、资源和帧率三个有限进程均退出码 0、VO 关闭、MMZ 回到 4900 KiB / 2 块。主机首次等待 UI 退出时，100 秒轮询上限早于设备的 240 秒定时器到期；随后读取确认正常退出，未截断测试。旧常驻 SIGTERM 的内核强制回收单独保存；后续测试的 39 行新增内核日志未见 OOM 或 MMZ 强制回收。

最终常驻 PID **31614**，停留 Image scaling 的 100%，Controls 保留 48%；无退出定时器，trace、QuickFill、事件录制和 WBC 关闭。常驻 RSS 15360 KiB、VmHWM 15360 KiB、VmPeak 33852 KiB、可用内存 23784 KiB。该常驻快照与上方独立性能窗口分开记录。

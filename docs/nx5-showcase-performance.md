# NX5 展示应用性能实测

2026-10-13，对已部署的 `308afe5` 六页应用进行实机性能测试。未修改应用或库代码；使用同一 SHA256 为 `81a87f5932fdf820c3295282b9af7afddffbc7aec080826958bf4b2a7a5cc01a` 的 ARM release 程序，仅在测试进程中开启 `SLINT_BRIDGE_TRACE`。设备、固件、SDK、分辨率和双页完成契约与 [部署记录](nx5-showcase.md) 一致。

## 帧率与资源

每个动态场景预热约 8 秒，然后连续测约 60 秒。界面导航、列表拖动和透明度滑块均由 **Slint 原生 MCP** 驱动；`drag_element` 以约 5 个逻辑像素为一步、16 ms 定时器间隔产生手势。性能窗口没有截图、WBC 或事件录制，独立 evdev 观察器也未捕获到实体输入，避免把用户操作混入自动负载。

帧率来自 NX5 板级完成回调：每 150 次成功 `present()` 后统计耗时，不使用 UI ticks。每个窗口丢弃第一段跨越开始边界的批次；下面仅计完整批次，共 41 批、6150 次成功提交。FPS 日志精度为 0.01，所有有效批次均显示 29.00。窗口末尾未满 150 帧的尾段不计入表格。

| 场景 | 完整批次 / 提交数 | 完成提交 FPS | RSS 范围（KiB） | CPU 中位数（单核 100%） |
| --- | ---: | ---: | ---: | ---: |
| Motion 六个运动图形 | 10 / 1500 | 29.00 | 14208–14212 | 29.1% |
| Devices 列表往返滑动 | 10 / 1500 | 29.00 | 14216–14220 | 66.4% |
| Layers 透明度连续变化，保留底图 | 11 / 1650 | 29.00 | 14224–14224 | 64.5% |
| Layers 透明开口，透明度连续变化 | 10 / 1500 | 29.00 | 14228–14228 | 63.6% |

列表测量窗口进行了 133 次拖动，每六次切换方向；两种透明场景各进行了 63 次滑块拖动。这里测的是这些重复交互负载下的提交吞吐，包含 MCP 手势间隔，不是脱离输入节奏的渲染极限测试。

资源观察器约每秒读取目标进程 `/proc/PID/status`、`stat` 和系统 `meminfo`；CPU 使用真实采样间隔及板上 `CLK_TCK=100` 计算，是进程总 CPU 相对一个核心的比例，非双核整机百分比。自动窗口内 RSS 约 13.9 MiB，进程累计 VmHWM 最大 14404 KiB（约 14.1 MiB）。系统可用内存最低 49968 KiB（包含结束静态窗口）。TDE MMZ 为 12100 KiB / 5 块，其中包括两块基础分配和三块 TDE 分配；它不能简单当作 Linux RSS。

起始静态窗口 RSS 为 13808 KiB；全部交互结束后静态窗口为 14228 KiB，保留 420 KiB，20 秒内稳定。四个动态窗口内部只变化 0–4 KiB，没有观察到持续爬升。这是有限时长观察，不能据此证明长期无泄漏。静态页 CPU 中位数仍约 15.5%，本轮未优化应用定时器或运行时等待策略。

**TDE 统计中的 copy、blend 均为 0，errors 为 0。** 当前运动图形、列表和带缩放/整体透明度的图片使用软件绘制路径；现有 TDE 纹理路径不接收缩放或整体 alpha 不为 255 的操作。因此这些结果不能作为硬件 TDE 混合吞吐成绩。约 29 FPS 与此前同板完成节拍一致，但本轮没有测每个物理扫描帧或接入实际视频层。

## 实体触摸响应

使用只读观察器打开实际 `gsl1686`，仅对自身 evdev 句柄选择 `CLOCK_REALTIME`；不独占输入、不注入事件、不访问 framebuffer、不加载 SDK。用户实体操作期间没有 MCP 输入注入或截图。Slint 原生 MCP 记录的时间戳位于事件分派处理后，因此以下差值包含处理回调；不是触摸传感器到 LCD 扫描的端到端时延。

第一次长窗口产生 1269 条事件，超过 MCP 的 1024 条环形记录容量，最早 245 条被覆盖。完整 evdev 与残存 MCP 记录均保留，该窗口被分析器拒绝用于完整配对统计；这不等于 evdev 或 UI 丢失输入。

随后短窗口完整采到 **7 次接触、14 条按下/抬起边沿、240 条 Slint 事件**。240 条全部 Accepted，记录丢失/未知均为 0；14 条边沿按顺序、类型和坐标与内核完整 `SYN_REPORT` 一一对应。用户确认本轮响应正常。

| 操作 | 边沿样本数 | 中位数 | 最大观测差值 | 加 1 ms 时间戳量化裕量 |
| --- | ---: | ---: | ---: | ---: |
| Motion 页内按钮 | 6 | 2.066 ms | 4.236 ms | 5.236 ms |
| Devices 页内滑动 | 2 | 0.263 ms | 0.684 ms | 1.684 ms |
| Layers 页内滑块 | 2 | 0.907 ms | 1.607 ms | 2.607 ms |

全部 14 条边沿（含导航）的中位数为 **1.756 ms**，最大为 **59.734 ms**，加量化裕量为 **60.734 ms**。这个最高值发生在 **Motion → Devices 的导航抬起事件**；Devices → Layers 的导航抬起为 15.097 ms，加裕量为 16.097 ms。它们与页内控件分开列出，不能把切页成本隐藏在平均数里。尚未对切页回调内部逐段剖析。

两个约 -0.16 ms 的值来自 MCP 毫秒时间戳截断，不解释为负延迟。样本量较小，表格是本次实际操作的范围，不是延迟保证或长期分位数承诺。记录和导出期间的 VmHWM 达到 17164 KiB（约 16.8 MiB），与关闭事件录制的自动性能窗口分开记录。

## 恢复与证据

测试后切到静态页，确认 `fb-present` 等待队列，再停止 trace 进程。首次恢复启动发生在旧进程锁尚未完全释放时，PID 3765 被 `DisplayNotAdmitted` 拒绝；原始日志保留。重新确认旧 PID 消失、VO 关闭、MMZ 4900 KiB / 2 块且锁已释放后，PID **3782** 正常启动并经原生 MCP 确认总览正常。不能只凭 `/proc/PID/exe` 链接消失认定所有线程和设备引用均已释放。

常驻仍为原 `308afe5`，日志为 `/tmp/slint-bridge-showcase-308afe5/live-after-performance-2.log`；trace、事件录制和观察器均已关闭，`f963558` 回退保留。恢复后的快照为 RSS / VmHWM 12164 KiB、3 个线程、MMZ 12100 KiB / 5 块；这是新进程启动后的状态，不是暖缓存状态。信号停止测试进程的内核 MMZ 回收单独保留，不改记为本轮正常析构测试。

原始证据位于本地 `evidence/nx5-showcase-performance/2026-10-13/`，不随 Git 分发：`automatic-02/` 含阶段边界日志，`resources.log` 为自动窗口资源/evdev 数据，`physical-resources.log` / `physical-mcp.json` 保留首次超容量窗口，`physical-short.log` / `physical-short-mcp.json` 为完整补采，`results.json` 为汇总，`cleanup/` 保存设备原始文件校验归档。测试工具、重放命令和分析器边界检查见 [设备工具](../test-app/tools/nx5/README.md#展示应用性能采样)。

# 启动触摸自动识别：四板验证

2026-10-22。开发分支 `wshl/auto-touchscreen`，基于 `main` 的 `2b4b185`。
新增 `InputDevice::auto_touchscreen()` / `--touch=auto`；手动路径和默认无输入行为保留。
当前筛选、错误与生命周期规则集中维护在[平台说明](software-platform.md#统一-api)。
本轮没有加入热插拔、独立触摸旋转或新的多点解码协议。

## 实现与主机验证

启动扫描只查询 `/dev/input/event*` 的 evdev 能力和有效轴范围；不按编号或设备名挑选。
合格候选必须唯一，存在无法完整检查的设备时也拒绝猜测。已经检查过的 File 直接交给解码器，
不按路径重新打开。初始化后沿用原事件循环，不持续扫描设备。

- 七项私有回归覆盖有/无 DIRECT 属性的单点、Type-A、slot/单点兼容、非触摸/笔/触摸板排除、
  多候选、权限/消失错误、无候选及拒绝诊断；文件替换测试证明最终保留的是最初打开的描述符。
- 测试应用的公开接口回归确认默认不启用自动识别、自动输入计入“最多一个触摸设备”的限制；
  CLI 回归确认 `auto` 与显式路径选择不同配置。
- 八种板级 feature 的 workspace 测试与互斥拒绝矩阵通过。
- `cargo fmt --all --check`、主机 NX5/TDE/MCP Clippy（全部 target、`-D warnings`）、
  NX1 ARM/MCP release Clippy 通过；公开 API 文档构建通过。
- NX1、NX5、X9、F1 的 release showcase 交叉构建通过，均开启原生 MCP 和元素调试信息。

候选歧义、权限错误和路径替换是主机模拟验证，不宣称在板上插入了第二块触摸屏或改变了设备节点。

## 四板正式对照

每台依次运行自动和手动模式，各 120 秒，使用同一新二进制、字体、显示参数与原生 MCP。
F1 测试二进制来自本分支，未混入另一个内存优化备选分支的实现。

| 设备 | 自动选择 | 协议/轴范围 | 旋转 | 自动/手动退出码 |
| --- | --- | --- | --- | --- |
| NX1 | `/dev/input/event2`，`gt911_ts` | 单点，X 0..1024 / Y 0..600 | 0° | 0 / 0 |
| NX5 | `/dev/input/event0`，`gsl1686` | 单点，X 0..1024 / Y 0..600 | 0° | 0 / 0 |
| X9 | `/dev/input/event1`，`gt9xxnew_ts` | Type-A，X 0..800 / Y 0..1280 | 90° | 0 / 0 |
| F1 | `/dev/input/event0`，`gsl1686` | 单点，X 0..1024 / Y 0..600 | 0° | 0 / 0 |

NX1/X9 的属性含 DIRECT；NX5/F1 的属性为空，实测覆盖了旧驱动兼容分支。
NX1 的 headset/keypad 与 X9 的 RTC power 节点被排除。

每种模式均通过真实 evdev 节点注入四组完整按下/释放，分别触发进入 Controls、应用配置、
打开重置对话框、取消对话框；原生 MCP 查询验证每一步 UI 状态。注入器先检查没有已有按下接触。
X9 将逻辑控件坐标反算到旋转前面板坐标，验证了自动选择与原 90° 输入映射共同工作。
随后每种模式完成九页 MCP 导航。合计 **32 组 evdev 点击、72 次页面导航、8 次正常限时退出**。
自动模式启动日志报告选择结果；手动模式没有自动扫描日志，实际操作同样成功。

这验证了节点选择、evdev 接收/解码、坐标转换、UI 回调和正常退出，
**没有验证本轮手指接触传感器、实体四角校准、多屏关联、热插拔或纯 Type-B**。
未截图，也不以本次结果扩大显示页退休、扫描输出或硬件加速故障恢复保证。

## 准备阶段问题与恢复

切换前重新核对 boot、当前程序路径/starttime、恢复依赖及线程等待状态。
NX5 有两次空闲检查未通过，脚本当时没有终止旧进程；重新确认主线程 poll、提交线程 futex 等待后才切换。
旧 NX5 常驻使用 TERM 结束时，驱动打印了强制清理旧 MMZ/VO 的提示；不把这种切换当作正常析构验证。
正式候选的八次退出均由应用自身限时结束，返回 0。

X9 首次准备启动因旧常驻结束后控制台仍在 graphics 模式而被显示准入拒绝，尚未进入自动输入选择。
使用仓库既有 `recover-console`，取得独占锁并等待匹配 DRM 完成事件后恢复文本模式，再进行正式对照。
未绕过或放宽显示准入；这一准备失败保存在独立日志中，不计作触摸识别通过。

正式对照结束后恢复四台原二进制及字体/SDK/旋转配置，保留原部署和启动脚本；
F1 恢复其原内存优化备选版。恢复会建立新进程，不保留原模拟会话计数。
通过进程路径、启动日志和原生 MCP 查询确认恢复；新功能没有写入固件自启动配置。
四板各 19 份小型设备文件已归档并核对 MD5，临时测试目录和四个转发已移除；
三个本次启动的 TCP adbd 经身份校验后结束，F1 原有 USB adbd 保留。

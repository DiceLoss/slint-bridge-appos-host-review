# NX5 富列表脏区与绘制优化

2026-10-14，实现 `7a3195c` + alpha 修正 `2fddc04`，配套 Slint `9a1a3b1`。基线为[源缓存优化](nx5-rich-bottleneck.md)的 `1225593` + Slint `22804ff`；同一 NX5 #233、启动 ID `4aa4f5d2-8de2-42cb-9c2b-44c3e74d6e2b`。目标是在保留 100 项内容、布局与视觉效果的前提下接近板级约 29 FPS 的提交上限。

## 剩余成本与改动

逐帧计时发现，列表外层裁剪没有阻止每项内部节点参与脏区遍历，纵向每帧仍访问 1279 个节点。在 `RichItem` 根矩形上增加 `clip: true`，使屏幕外子树可以被跳过。全部 100 个实例、模型、滚动范围和布局保留，未引入虚拟列表。该条目的原有内容都在自身边界内，包括 PNG 自带阴影；像素回归覆盖裁剪边缘及离屏更新后重新进入视口。

纵向裁剪对照使用同一个诊断二进制切换开关。各行存在包含关系，不能相加；绘制包含 TDE，物理页写入另计。

裁剪后纵向脏区/绘制访问约 317 个节点，横向约 332 个。脏区明显下降，但图像绘制几乎不变，因此继续处理以下实测路径：

- **SVG 栅格结果复用。** Slint 原先对同一已解析 SVG、同一物理目标尺寸重复栅格化。新增每线程最多 32 项、像素总量不超过 2 MiB 的 LRU 缓存，以解析对象的弱身份和精确目标尺寸为键，每个源只保留一个尺寸。弱引用不保留解析树，插入时清除失效源；过大结果不缓存，`no_std` 仍直接绘制。共享像素保持写时复制，尺寸变化重新栅格化。
- **预乘像素直接复制。** 已预乘且整体 alpha 为 255 时直接 `memcpy`；其他路径继续原有转换。PNG 解码结果本来已预乘，无需改变应用解码或资产。
- **批量检查目标 alpha。** ARM NEON 每批检查 16 个实际目标像素，尾部逐像素检查；没有绕过“不透明目标”准入。透明目标仍走软件混合。
- **批量恢复目标 alpha。** SDK 的混合结果可能将不透明 alpha 舍入为 254。保留作业成功并完成缓存同步后的精确 255 修正，改用 NEON 连续字节读改写，尾部逐像素处理；未知 DMA 时仍禁止 CPU 访问。尝试省掉此步骤的候选版本被完整物理页验证否决，详见下节。
- **增加一个小源槽。** 保留两个全幅源槽，增加容量为四分之一画布字节加 padding 余量的槽，容纳交替卡片底图。Rust 与 C 都在使用前检查容量；沿用按使用帧和源大小的替换策略。1024×600 下增加 620 KiB MMZ，避免另加一个全幅槽。

表中“组合中间版”包含 SVG 缓存、直接复制、NEON 检查与当时的 NEON alpha 修正，仍为两源槽。最终版随后加入小源槽，并保留 NEON alpha 修正；不能把中间版计时作为最终版分项成绩。横向剩余文本约 8.8 ms、脏区约 2.5 ms 和同步 TDE 工作仍有成本。所有临时计时、开关和采样代码均已移除，最终性能另测。

## 正确性与回归

新增真实 Showcase 的 25 状态回归，使用独立 `NewBuffer` 参考与连续 `ReusedBuffer` 对照，覆盖横纵奇数/小数偏移、首末端、选择、离屏模型改变和重新进入视口。优化前后保存的 25 张 1024×600 RGBA 整帧共 **15360000 像素，逐字节一致**。首次尝试把已预乘 PNG 转回普通 RGBA 再预乘，被此检查检出 263 个像素的 1 级误差；该变体未部署，已撤销，原始失败证据保留。

真实 Slint 背景加交替前景回归验证小源槽：连续 8 帧变化位置时前景上传从 32 次降至 16 次，背景仍命中。Slint 四项缓存回归覆盖重复使用、尺寸与原始栅格结果比对、写时复制、独立源/弱引用释放及容量上限。Slint core 344 项单元测试、73 项文档测试通过，11 项文档测试按原配置忽略；严格库 Clippy 通过。首次 Clippy 提示线程局部初始化可以为常量，修复后复验通过；原有测试代码的未使用函数警告单独保留。

本仓库 feature 矩阵、格式、严格 workspace Clippy、原生 ASan/UBSan 故障与边界测试、ARM 交叉构建通过。原生回归检查长度 0–65、偏移 0–15 的所有 alpha 位置、复制保护区、小源槽 padding 与越界拒绝，以及 256 组奇数位置/裁剪/透明度像素组合；未知 DMA 时禁止 CPU 写页。独立 ARM CPU 测试在板上确认 `NEON=1` 并正常退出。

最终源码的 `nx5_hardware_compare` 与 `nx5_demo_pages_match_full_frames` 分别通过，包含硬件混合、整体透明度、裁剪、写时复制、增量重绘与 100 帧双页对照。不透明复制精确一致，混合最大通道误差不超过既有阈值 1。两项正常退出后 VO 关闭，MMZ 回到 4900 KiB / 2 块。新增断言要求这些不透明画布的输出 alpha **精确为 255**，不再让 RGB 的 1 级容差掩盖 alpha 差异。

候选版与修正版分别执行完整应用原生 MCP；在横纵两方向完整观察到全部 100 个稳定 ID，宽幅拖动、锁定轴、拖动不误选、首末端夹紧和选择通过，各完成六张受内存检查保护的截图。修正版截图前可用内存最低为 22624 KiB，高于 16384 KiB 保留线。截图是软件重绘参考，物理页另行读取核对。

## 被整帧检查否决的 alpha 捷径

`7a3195c` 曾试用 SDK 背景 alpha 输出，省掉 CPU 修正。该候选完成了硬件 RGB 容差测试与完整交互，测得纵向 27.54、横向 26.83 FPS；这些数字**不作为最终交付性能**。

完整 1024×600 物理页读回进一步发现：纵向 11 个、横向 15 个像素与软件参考最大通道差为 2，超过既有 1 级阈值。纵向 27598 个、横向 19245 个像素的物理 alpha 为 127，参考应为 128。源画布 alpha 254 经反预乘会放大 RGB 舍入差，再经板级 alpha 编码变成 127。旧 `1225593` 在相同位置重新采集的完整物理页全部 alpha 为 128、最大 RGB 差为 1；两版本的软件参考逐字节一致，证实是新增硬件路径回归。

`2fddc04` 撤回背景 alpha 选项，恢复完成后精确 alpha 修正，保留 NEON 加速。原生 SDK 替身不再替被测代码补 alpha；该回归先失败、修复后通过，并新增真实硬件不透明 alpha 精确断言。ARM 短尾部、非对齐与保护区回归重新通过。此后硬件、UI、性能和整帧物理页全部以修正版重新采集；原失败数据、旧版对照及候选性能保留在 `full-alpha-regression.json`、`baseline-full/` 和顶层 `*-fps/`，未改写为通过。

## 正式版性能与常驻

正式二进制不含分段探针。CPU/RSS 与 FPS 使用独立新进程，资源窗口关闭 trace、截图和录制，以设备 uptime 与 CPU ticks 差分计算单核 CPU；FPS 只取原有每 150 次成功 PAN 的低频日志。预热至少 8 秒，资源至少 45 秒、FPS 至少 90 秒，丢弃跨开始边界的首批；每次手势检查真实位移并保持在列表内部。原生 MCP 查询、手势插值及等待均包含在负载中。基线来自上一轮同启动正式程序，属于顺序对照，未进行多轮随机化试验。

| 方向 | 完成提交 FPS：基线 → 新版 | 提升 | 单核 CPU：基线 → 新版 | 新 RSS 均值 / 范围（MiB） |
| --- | --- | --- | --- | --- |
| 纵向 | 17.52 → **27.52** | **57.0%** | 89.53% → 78.66% | 17.91 / 17.86–17.93 |
| 横向 | 15.51 → **26.03** | **67.8%** | 91.72% → 85.99% | 18.27 / 18.17–18.34 |

纵向资源窗口 46.76 秒 / 27 次手势；FPS 窗口 90.64 秒 / 52 次手势，统计 2250 次有效完成提交，批次范围 27.19–27.71 FPS。资源窗口 3 线程，新增 major page fault 为 0。
横向资源窗口 47.11 秒 / 8 次手势；FPS 窗口 94.23 秒 / 16 次手势，统计 2250 次有效完成提交，批次范围 25.89–26.13 FPS。资源窗口 3 线程，新增 major page fault 为 0。

本轮诊断前设定的 **28 FPS 检查线未通过**，没有放宽判据或宣称达到 29 FPS。相对基线已有明显改善，仍有软件文字绘制、脏区和同步 TDE 工作，帧间调度也包含在实际完成提交吞吐中。前述中间版分项仅用于解释优化方向，不能据此精确拆分正式版剩余差距。

纵向 TDE 计数覆盖 2400 个绘制帧：复制 0.98 / 帧，混合 3.03 / 帧，源缓存按调用计命中率 55.96%，错误 0。缓存次数比例不是 TDE 硬件忙碌率。
横向 TDE 计数覆盖 2250 个绘制帧：复制 0.99 / 帧，混合 3.28 / 帧，源缓存按调用计命中率 54.45%，错误 0。缓存次数比例不是 TDE 硬件忙碌率。

MMZ 实测 **12760 KiB / 6 块**，比基线增加 **620 KiB / 1 块**，与小源槽一致。SVG 缓存另受每线程 2 MiB / 32 项限制，属于普通内存而非 MMZ；上表 RSS 是实际资源窗口观测值，不能把缓存上限当成实际增量。

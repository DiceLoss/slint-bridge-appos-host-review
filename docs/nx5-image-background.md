## 与纯色版本对照

沿用相同的原生 MCP 驱动脚本：每个动态场景预热约 8 秒、采样约 60 秒，不截图、不录制 MCP 事件；只读资源观察器未检测到混入自动窗口的实体输入。帧率取每 150 次成功显示提交的耗时，丢弃第一段跨边界批次。本轮有效批次共 39 批、5850 次提交；不使用 UI ticks。

| 场景 | 纯色 FPS | 图片版 FPS | 图片版 RSS（KiB） | CPU 中位数：纯色 → 图片（单核 100%） |
| --- | ---: | ---: | ---: | ---: |
| Motion 动画 | 29.00 | 29.00 | 20900–20968 | 29.1% → 80.9% |
| Devices 列表滑动 | 29.00 | **20.37** | 20968–20968 | 66.4% → **100.0%** |
| 图片底图上的透明度变化 | 29.00 | 29.00 | 20972–20972 | 64.5% → 66.4% |
| 关闭图片后的透明开口 | 29.00 | 29.00 | 20972–20972 | 63.6% → 70.9% |

列表八个有效批次为 17.68、20.86，以及六个 20.81 FPS，按批次实际耗时汇总为 20.365 FPS，比纯色版低约 **29.8%**。约 61 秒内完成 53 次 MCP 拖动，纯色版约 60 秒为 133 次；原生手势的定时器也受 UI 工作量影响，因此这里是相同驱动方式下的实际交互吞吐，不是固定外部输入频率的压力测试。其余三个场景分别统计 1500、1500、1650 次完成提交，各批次为 29.00 FPS。

图片版动态 RSS 约 **20.5 MiB**，比纯色版约高 **6.6 MiB**；自动测试进程 VmHWM 为 **24668 KiB（24.1 MiB）**，包含图片首次解码等启动成本。初始静态 RSS 为 20164 KiB，结束静态为 20976 KiB，保留 812 KiB；各测量窗口内基本稳定，不能由这段有限测试断言长期无泄漏。自动阶段最低系统可用内存为 34428 KiB，包含当时临时保留的三个程序版本，不能把全部系统差值算成图片堆内存。

TDE `copy=0`、`blend=0`、`errors=0`。原图大于显示尺寸且使用缩放，当前 TDE 路径不支持这类操作；本轮测的是软件图片绘制与混合。列表的进程 CPU 接近单核 100% 刻度，显示提交吞吐下降，说明这类图片界面比纯色用例更容易暴露软件绘制成本；尚未做函数级剖析或优化。

## 实体输入

第一轮实体等待期间没有 evdev 事件，900 秒有限测试到期退出，用户反馈“没有界面”。随即确认旧进程、VO 和锁释放，恢复不带退出定时器的图片版常驻进程，并用原生 MCP 截图确认画面。此空窗属于测试调度，不是图片程序崩溃；首次空输入日志保留，没有据此生成时延成绩。

后续在关闭 trace 的常驻进程上重新采样。只读 evdev 观察器早于 MCP 录制启动，记录了较早的两次完整接触；这些接触在 MCP 第一条事件之前超过 21 秒结束。按双方共同覆盖的连续区间配对，得到 **16 次接触、32 条按下/抬起边沿、488 条 MCP 事件**，无记录丢失/未知。485 条 Accepted、3 条 Rejected 均保留。没有删除中间不匹配事件，原始文件不改写；截取边界与排除范围见 `physical-overlap-scope.json`。

内核 `SYN_REPORT` 到 Slint 事件处理完成（包含回调）的中位数 **2.755 ms**，最大 **55.580 ms**；加 1 ms 时间戳量化裕量为 **56.580 ms**，最高仍发生在 Motion → Devices 的导航抬起。页内 Motion 操作最大观测差值 27.958 ms（22 条边沿，含速度/过渡/暂停等操作），列表一次滑动为 0.647 ms（2 条），Layers 一次拖动为 0.587 ms（2 条）。微小负值来自毫秒时间戳截断。

本轮手动动作与上一轮不同、样本量有限，而且使用了关闭 trace 的常驻进程；不将两个中位数相除作为图片引起的延迟百分比。这里也不包含传感器扫描或 LCD 扫描。用户在画面恢复后确认“已完成，响应正常”。

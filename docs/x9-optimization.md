# X9 富列表绘制与写页优化

2026-10-14 至 15 日（北京时间），在同一 X9 / Lombo N7、Linux `3.10.100 #452` 上分解富列表滑动成本并复测。物理 800×1280、逻辑 1280×800、顺时针 90°，同一 DejaVuSans.ttf、100 项内容、PNG/SVG 与文字、`interactive` governor；没有改界面、降低分辨率、裁剪精度或增加物理页。

基线为库 `8604707`、Slint `ea7d0ae`、`showcase-06`，正式 FPS/资源基线见 [原性能报告](x9-performance.md)。优化使用库 `cacf98f`、Slint `fa6a6d0`、正式 `showcase-07`，ELF SHA256 `0ea44d41b3252118e26cdb501b4401aaeb09456d83303adbd804ce751f12156e`，13,698,344 字节；比基线增加 452 字节。阶段计时程序单独构建，未用于正式资源/FPS 结果。

## 瓶颈与旋转对照

软件 renderer 在纹理采样时直接写旋转后的保留画布，没有独立的全屏旋转复制阶段。采用 [离屏对照工具](../test-app/tools/x9/README.md#绘制阶段对照)，在设备 CPU 上运行同一真实 Showcase、同一滚动状态，分别设置 0°/90°。每帧固定滚动 8 个逻辑像素，预热 20 帧后取 60 帧均值；不含 framebuffer 写页、提交或 MCP 手势。

| 场景 | 基线 0° 绘制 | 基线 90° 绘制 | 基线旋转增量 | 优化 0° 绘制 | 优化 90° 绘制 | 优化旋转增量 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 纵向 | 60.71 ms | 128.15 ms | 67.44 ms | 62.51 ms | 90.47 ms | 27.97 ms |
| 横向 | 41.31 ms | 79.48 ms | 38.16 ms | 42.64 ms | 58.91 ms | 16.27 ms |

旋转增量是两种方向的整段 render 差，包含采样/缓存和其他方向相关绘制影响，不能当作单独函数耗时。0° 单轮结果约慢 3%，本轮未进一步分离代码布局与测量波动；主要验证对象为 X9 的 90° 部署。

旋转纹理原路径沿目标扫描行读取源图列，访问不连续。改为 32×32 分块后，连续处理相邻源列，保留原来的采样坐标、颜色转换、混合与脏区规则。仅对 90°/270°、宽高至少 64 像素的 RGB/RGBA 纹理启用；没有新增图片缓存、堆分配或画布。主导成本因此下降，但不旋转时整段绘制仍需约 60/40 ms，基础绘制成本依然显著。

同样测过两种候选，均与基线四张 RGBA 全图逐字节一致：

| 分块 | 纵向 90° | 横向 90° |
| --- | ---: | ---: |
| 32×32（采用） | 90.47 ms | 58.91 ms |
| 8×64 | 114.79 ms | 73.45 ms |
| 64×16 | 88.97 ms | 68.37 ms |

64×16 的纵向略快，但横向更慢；采用两轴更均衡的 32×32。分块过窄增加调度开销，不能只凭缓存大小选择参数。访问局部性的解释来自代码路径和上述对照收益，本固件没有启用 PERF_EVENTS，未采集硬件 cache-miss 计数。

## 正式运行路径的阶段耗时

临时探针围绕 render、各次写页分段及 PAN/匹配完成等待计时。原生 MCP 在列表内部预热后，每轴执行三次宽幅拖动，去掉每类首尾各两个记录。下表用中位数，避免每次手势结束时少量轻量 UI 重绘混入主列表绘制；写页为各次调用内经过时间之和，包含区域整理、像素转换和映射存储，不含完成等待、分段之间处理输入的时间及提交前内存屏障。

| 阶段 | 纵向基线 → 优化 | 横向基线 → 优化 |
| --- | ---: | ---: |
| 绘制（含旋转） | 128.52 → **91.09 ms** | 79.92 → **59.66 ms** |
| framebuffer 写页 | 19.06 → **5.09 ms** | 11.83 → **3.17 ms** |
| 写入像素数 | 432,000 → 432,000 | 约 262,000 → 约 262,000 |
| 写页分段数 | 17 → 5 | 12 → 4 |
| PAN ioctl | 0.076 → 0.076 ms | 0.076 → 0.076 ms |
| 提交到匹配事件完成 | 8.48 → 8.06 ms | 8.22 → 8.78 ms |

纵向基线/优化分别有 143/284 笔写页，横向 456/459 笔。完成等待在后台与下一帧绘制重叠，不能将所有阶段简单相加来预测帧率。PAN 返回远早于匹配事件，仍不作为旧页可复用的依据。

写页优化针对当前不透明 BGRA8888 场景：先按整段检查 alpha，再批量交换 R/B，移出逐像素透明度分支；只有对齐、至少 16 像素、alpha 量程 255 的全不透明段进入快路径。透明像素、短尾部、其他格式和 alpha 量程沿用原精确转换。此路径无额外内存；NX5 TDE 既有转换入口优先，不改变 NX5 的 0–128 量程。

两张物理页、至多一笔在途提交和一帧预渲染均保持原约束。完成等待在写页之前，页状态仅在匹配事件及布局复核成功后更新；错误隔离、约 1 ms 写页预算和提交顺序没有修改。

## 正式 FPS 与资源复测

仍使用原生 MCP 相同手势、列表内部预热至少 10 秒、每轴连续滑动至少 60 秒。CPU/RSS 使用不含探针的新进程（本次 PID 2879）；FPS 使用另一新进程（本次 PID 2949）与基线同一计数库，按成功匹配的完成事件计数。两个窗口均不截图、不录制输入；统一剔除阶段边缘。

| 场景 | 基线 FPS → 优化 FPS | 提升 | CPU 基线 → 优化（单核 100%） | RSS 基线 → 优化 |
| --- | ---: | ---: | ---: | ---: |
| 纵向连续滑动 | 6.64 → **10.21** | **53.7%** | 98.14% → 98.16% | 17.53 → 17.50 MiB |
| 横向连续滑动 | 10.73 → **15.55** | **44.9%** | 98.31% → 98.17% | 17.75 → 17.73 MiB |

CPU 仍接近一个满核，收益表现为同样负载下完成更多帧。没有以降低帧率或删除内容换取 CPU 下降；当前吞吐仍未达到 30/60 FPS。

| 优化场景 | 有效 FPS / 资源窗口 | 完成帧数 | 帧间隔中位数 / P95 / 最大值 | RSS 范围 |
| --- | ---: | ---: | ---: | ---: |
| 纵向 | 62.11 / 62.11 s | 634 | 94.55 / 110.33 / 142.34 ms | 17.43–17.53 MiB |
| 横向 | 66.12 / 66.12 s | 1,028 | 63.03 / 63.07 / 220.63 ms | 17.70–17.77 MiB |

基线纵向 P95 为 157.61 ms，横向 94.58 ms，均下降。横向最大间隔却高于基线 157.67 ms，本轮仍有长间隔，不能声称所有帧抖动都改善。间隔包含 MCP 查询与手势调度，不等于实体触摸延迟。

两轮每轴各 7 个完整手势；纵向动作窗口约 65.84–65.85 秒，横向约 69.34–69.40 秒。计数探针共记录 2,237 个匹配完成事件，错误标志为 0。静态 Controls、停止滑动及返回 Controls 均为 0 次新提交；无探针静态 CPU 约 0.33%–0.50%。全程 3 个线程，无新增 major page fault。滑动基本为 912 MHz；资源纵向有一个 600 MHz 样本，计数纵向有一个 504 MHz 样本，未改 governor 或强制频率。

探针与无探针的滑动 CPU 相差不足 0.05 个百分点，RSS 多约 23/48 KiB，主表仍采用无探针结果。双 framebuffer 为既有 7.81 MiB I/O 映射，不计入进程 RSS；tmpfs 部署文件也占 RAM，不能与 RSS 简单相加。RSS 范围仅代表本轮短窗口，不构成长时间泄漏测试。

## 像素与验证范围

- Slint renderer 全部 9 项库测试通过。新增 576 组扫描行/分块对照覆盖 RGB/RGBA/预乘 RGBA/AlphaMap、四个旋转方向、缩放、纹理偏移、透明度、着色、裁剪与重叠脏区，比较完整缓冲和未触及区域。
- X9 上四组离屏 RGBA 输出共 **4,096,000 像素**与基线逐字节一致；源/目标脏像素面积一致。
- 最终无探针版本完成八页原生 MCP 回归、19 张过程截图及一张收尾截图，包含富列表双向拖动、PNG/SVG 四档缩放、透明层、弹窗和普通设备列表双向边界/选择；记录无丢失或未知事件。截图前 MemFree 均高于 32 MiB，本轮最低约 81 MiB。
- 实际 Controls 48% 前台页 `yoffset=1280` 与 Scaling 125% 前台页 `yoffset=0`，分别与同字体、同 90° 旋转的独立 CPU 参考比较，共 **2,048,000 像素零差异、最大通道误差 0**。两张参考本身也与优化前正确字体配置的参考完全一致。该读回验证物理页内容，不等于面板扫描输出或实体手指验收。
- 新增写页回归覆盖长度 0/1/15/16/17/31/32/33/63/64/65、源字节偏移 0–3、目标偏移 0–7、透明度边界、alpha 量程 128/255 与前后保护字节。原逐通道/alpha 穷举和格式转换回归继续通过。三项转换测试亦在 X9 ARM release 二进制运行通过。
- workspace feature 矩阵、`cargo fmt --all --check`、`nx5-tde,slint/mcp` 与 `fbdev,slint/mcp` 的所有 target 严格 clippy 通过；Slint renderer 严格 clippy 和格式检查通过。主机原生 TDE 故障注入、转换边界与 SDK 会话测试通过。
- X9 / NX5 交叉构建通过；X9 正式版 20 秒正常退出通过。没有部署或操作 NX5 实机，本轮不能作为 NX5 新版本的实机验收。
